التلخيص المترابط للموضوعات

تم دمج الأفكار المتشابهة والمكملة لبعضها من النصوص المدخلة تحت أقسام موضوعية واضحة للمذاكرة.

1. ## ١. المحور الأول: خريطة دليل تطوير الإضافات والمعمارية الأساسية (Plugin Handbook & Architecture)

تعليم ووردبريس

١.١ المفاهيم الأساسية لبنية الإضافة (Plugin Core Architecture)


إضافة ووردبريس ليست مجرد ملف ينفذ كود PHP عابر، بل هي توسعة ديناميكية (Dynamic Extension) تتكامل مع نظام ووردبريس دون التعديل على النواة (WordPress Core).

- خطافات البرمجة (Hooks): تشكل العصب المركزي للتفاعل، وتتكون من نوعين:
- الإجراءات (Actions): تُستخدم لإضافة وظائف جديدة أو تنفيذ كود عند نقطة معينة أثناء تحميل الصفحة (مثل: إرسال بريد، طباعة كود في الهيدر).
- المرشحات (Filters): تُستخدم لتعديل أو تغيير البيانات قبل عرضها أو حفظها (مثل: تعديل محتوى المقال، تغيير طول المقتطف).
- إدارة الكيانات والبيانات (Data & Entities): التعامل مع قاعدة البيانات عبر كيانات مثل (Custom Post Types, Taxonomies, Metadata, Users).
- واجهة التحكم والواجهة البرمجية (Admin UX & APIs): دمج لوحات التحكم عبر Administration Menus و Settings API، والتكامل الخارجي عبر HTTP API، والمهام المجدولة عبر WP-Cron.

١.٢ مخطط الكود الأساسي (Core Blueprint)


يوضح الكود التالي النمط المعياري لبداية أي إضافة وإشراكها في دورة النظام:

```php
/
* Plugin Name: Core Architecture Demo
*/

if ( ! defined( 'ABSPATH' ) ) {
exit; // حماية الإضافة من الوصول المباشر
}

// 1. التسجيل في نظام الـ Hooks
add_action( 'init', 'my_custom_post_type_init' );

function my_custom_post_type_init() {
// إنشاء Custom Post Type
register_post_type( 'book', [
'public' => true,
'label' => 'Books',
]);
}
```

> 💡 ملاحظة للمذاكرة: يُستحسن دائماً حماية ملفات الإضافة ومنع الوصول المباشر إليها لتفادي الأخطاء القاتلة وثغرات كشف المسارات.

2. ## ٢. المحور الثاني: أمان الإضافات وحماية الملفات من الوصول المباشر (Direct Access Security & ABSPATH)

تعليم ووردبريس

٢.١ آلية الحماية البرمجية (Technical Mechanism)


عند طلب رابط ملف الإضافة مباشرة من المتصفح (مثال: `http://site.local/wp-content/plugins/test.php`)، يحاول خادم PHP تنفيذ الملف منفصلاً دون تحميل بيئة ووردبريس (WordPress Environment).

- الثابت ABSPATH: يُعرّف في ملف `wp-config.php` عند إقلاع النظام ويحتوي على المسار المطلق للسيرفر.
- التحقيق الشرطي (Guard Clause):
- إذا تم الطلب عبر ووردبريس: تكون قيمة `ABSPATH` مُعرّفة مسبقاً، فيتجاوز الكود الشرط ويكمل التنفيذ.
- إذا تم طلب الملف مباشرة: تكون قيمة `ABSPATH` غير مُعرّفة `! defined('ABSPATH')`، فيتم تنفيذ `exit;` وإنهاء الاتصال فوراً.

٢.٢ تحليل الأخطاء القاتلة عند غياب الحماية (Fatal Error Analysis)


عند طلب الملف مباشرة بدون شرط الحماية، تظهر المشكلات التالية:

| الخطأ البرمجي | السبب التقني | الأثر الأمني والمعماري |
| :--- | :--- | :--- |
| `Fatal error: Call to undefined function add_action()` | محرك PHP حاول تنفيذ الدالة قبل تحميل دوال ووردبريس في الذاكرة. | تعطل السكريبت وكشف مسار الملفات الحقيقي على السيرفر (Path Disclosure Vulnerability). |
| `Warning: Attempt to read property "users" on null` | محاولة قراءة خاصية `users` من الكائن `$wpdb` بينما قيمته `null` لأن البيئة لم تبدأ. | كشف هيكل المجلدات والأخطاء الداخلية للزوار والمخترقين. |

٢.٣ الصيغة النموذجية لحماية الملفات

```php
// منع الوصول المباشر للملف
if ( ! defined( 'ABSPATH' ) ) {
exit;
}

// الكود البرمجي الآمن هنا
add_action( 'init', 'my_safe_function' );
```

> ⚠️ تنبيه امتحاني هام: وضع شرط فحص `ABSPATH` في أول سطر في جميع ملفات PHP الخاصة بالإضافة هو القاعدة الذهبية الأولى للأمان في ووردبريس.

3. ## ٣. المحور الثالث: تسلسل دورة إقلاع ووردبريس (WordPress Bootstrapping Process)

تعليم ووردبريس

٣.١ التسلسل الملفي لإقلاع النظام (Execution Flow)


عندما يطلب الزائر صفحة في الموقع، تمر الدورة بالتسلسل الملفي المُنظّم التالي:

1. `index.php` (المجلد الرئيسي): نقطة الدخول الأولى لجميع الطلبات؛ تستدعي `wp-blog-header.php`.
2. `wp-blog-header.php`: ينسق بين تحميل النظام وتجهيز الاستعلام والقالب؛ يستدعي `wp-load.php`.
3. `wp-load.php`: يبحث عن ملف الإعدادات وإذا لم يجد `wp-config.php` يوجه المستخدم لشاشة التثبيت؛ يستدعي `wp-config.php`.
4. `wp-config.php`: يتضمن إعدادات قواعد البيانات، ويُعرّف الثابت `ABSPATH`؛ ويستدعي في آخره `wp-settings.php`.
5. `wp-settings.php` (العصب البرمجي للإقلاع): يقوم بتحميل البيئة كاملة وفق الخريطة التالية:
- `wp-includes/load.php`: تحميل الدوال الأساسية وإدارة الأخطاء.
- `wp-includes/plugin.php`: تحميل نظام الـ Hooks (`add_action`, `add_filter`).
- `wp-includes/class-wpdb.php`: إنشاء الكائن العام `$wpdb` للاتصال بقاعدة البيانات.
- `wp-includes/default-constants.php`: تعريف الثوابت الافتراضية.
- تحميل الإضافات الإلزامية (`mu-plugins`).
- تحميل الإضافات القياسية المفعلة (`Active Plugins`).
- `wp-includes/pluggable.php`: تحميل دوال الأمان والتوثيق.
- تفعيل القالب النشط وقراءة `functions.php`.
- إطلاق الهوك الشهير `do_action('init')` لإعلام النظام باكتمل التحميل.
6. العودة إلى `wp-blog-header.php`:
- استدعاء دالة `wp()` لتشغيل الاستعلام الرئيسي (`Main Query`).
- استدعاء `template-loader.php` لتحديد وتمرير القالب المناسب لعرض الصفحة.

> 💡 ملاحظة للمذاكرة: يُعرّف الثابت `ABSPATH` تحديداً في ملف `wp-config.php` عبر الكود التالية:
```php
if ( ! defined( 'ABSPATH' ) ) {
define( 'ABSPATH', __DIR__ . '/' );
}
```

4. ## ٤. المحور الرابع: تحليل الأداء وتحسين كفاءة الإقلاع (Bootstrapping Performance & Caching)

تعليم ووردبريس

٤.١ هل تسبب كثرة هذه الاستدعاءات ثقلاً في الموقع؟


الإجابة: لا تسبب ثقلاً بح ذاتها إلا إذا سيء استخدامها.

- التنفيذ الفائق في الذاكرة (In-Memory Execution): استدعاء الملفات وتجهيز الثوابت هو مجرد تحميل شفرات برمجة في ذاكرة الـ RAM للـ PHP ولا يستهلك وقتاً في المعالجة (CPU Time).
- اتصال موحد بقاعدة البيانات (Single DB Connection): يتم فتح اتصال واحد فقط عبر الكائن `$wpdb` وتثبيت استعلام الاستكشاف الأساسي مرة واحدة.

٤.٢ مسببات الثقل الفعلي (Performance Bottlenecks)


تحدث البطء والكبوات داخل خطوة تحميل الإضافات نتيجة:
1. الإضافات السيئة (Bloated Plugins): تنفيذ استعلامات SQL ثقيلة ومباشرة عند لحظة الإقلاع (`init` أو `plugins_loaded`) دون الحاجة إليها.
2. الأفعال المتكررة: ربط وظائف تستهلك موارد عالية دون استخدام كاش (`Caching`).

٤.٣ الحلول التقنية لتسريع الأداء


- OPcache: ذاكرة التخزين المؤقت للشفرات البرمجية لتجنب إعادة تحليل (Parsing) ملفات PHP في كل طلب.
- Object Caching (Redis / Memcached): تخزين نتائج استعلامات قاعدة البيانات في الذاكرة الفائقة.

5. ## ٥. المحور الخامس: التعامل المتقدم والآمن مع قاعدة البيانات عبر الكائن ($wpdb)

تعليم ووردبريس

٥.١ مفهوم الكائن العام `$wpdb`


الكائن `$wpdb` هو الطبقة البرمجية العازلة والمعتمدة (Database Abstraction Layer) للتعامل مع قاعدة بيانات ووردبريس بالكامل.

- استدعاء النطاق العام (Global Scope): كلمة `global $wpdb;` تجلب الكائن المُنشأ في مرحلة الإقلاع لتجعله متاحاً داخل نطاق الدوال.
- البادئة الديناميكية (Dynamic Table Prefix): بدلاً من كتابة `wp_users` بشكل صلب، نستخدم `$wpdb->users` أو `$wpdb->prefix . 'users'` لضمان توافق الكود عند تغيير البادئة.

٥.٢ أمثلة برمجية واستعلامات آمنة

```php
if ( ! defined( 'ABSPATH' ) ) {
exit; // الحماية من الوصول المباشر
}

function get_active_users_demo() {
// 1. الإعلان عن الكائن العام داخل الدالة
global $wpdb;

// 2. كتابة الاستعلام بالبادئة الديناميكية
$query = "SELECT * FROM {$wpdb->users}";

// 3. تنفيذ الاستعلام وجلب النتائج ككائنات
$users = $wpdb->get_results( $query );

if ( ! empty( $users ) ) {
foreach ( $users as $user ) {
// التعامل مع البيانات
}
}
}
```

٥.٣ ملخص أساليب `$wpdb` الأساسية

| الدالة / الخاصية | الاستخدام التقني |
| :--- | :--- |
| `$wpdb->get_results()` | جلب مصفوفة كائنات من عدة صفوف (Multiple Rows). |
| `$wpdb->get_row()` | جلب صف واحد فقط من قاعدة البيانات (Single Row). |
| `$wpdb->get_var()` | جلب قيمة واحدة فقط (مثل حساب عدد المسجلين `COUNT(*)`). |
| `$wpdb->prepare()` | تأمين البيانات والتعديل والوقاية من ثغرات حقن SQL Injection. |

شبكة ربط المفاهيم والمقارنات

توضيح أوجه التكامل والاختلاف والسبب والنتيجة بين المحاضرات والمصادر.

مقارنة بين الإجراءات (Actions) والمرشحات (Filters)

مقارنة واختلاف

تُستخدم Actions لتنفيذ كود وإضافة وظائف عند نقطة محددة دون إرجاع قيمة، بينما تُستخدم Filters لتعديل البيانات وتمريرها وإرجاعها بعد التعديل.

💡 خلاصة الربط والامتحان:

استخدم Action عند الرغبة في طباعة كود أو إرسال بريد، واستخدم Filter عند الرغبة في تعديل نص أو مقتطف قبل عرضه.

الوصول المباشر وتأثيره على الثابت ABSPATH

سبب ونتيجة

فتح ملف الإضافة مباشرة يتجاوز ملف wp-config.php مما يجعل الثابت ABSPATH غير معرف، وينتج عنه فشل الدوال والنواة.

💡 خلاصة الربط والامتحان:

فحص defined('ABSPATH') يمنع تنفيذ الملفات المنفصلة ويحمي الموقع من ثغرات كشف المسارات.

دورة الإقلاع وتوفر الكائن العام $wpdb

تطور أو تسلسل

الكائن $wpdb يتم إنشاؤه داخل wp-settings.php في الخطوة الخامسة من الإقلاع، ولذا لا يمكن استدعاؤه بدون مرور الطلب عبر تسلسل الإقلاع الطبيعي.

💡 خلاصة الربط والامتحان:

إعلان global $wpdb لا يعمل إلا إذا تم تحميل بيئة ووردبريس بالكامل أولاً.

كتابة البادئة الصلبة مقابل البادئة الديناميكية $wpdb->prefix

تكامل وإضافة

كتابة اسم الجدول مثل wp_users قد يسبب كسر الكود إذا قام المستخدم بتغيير بادئة الجداول في wp-config.php، بينما $wpdb->users يضمن العمل في جميع البيئات.

💡 خلاصة الربط والامتحان:

اعتماد $wpdb->prefix يضمن المرونة والتوافق البرمجي الكامل للإضافة.

جدول التعاريف والمصطلحات الأكاديمية

المصطلح / المفهوم التعريف الأكاديمي مثال أو سياق المصدر
ABSPATH ثابت برمجي يُعرّف المسار المطلق لدليل ووردبريس على السيرفر، ويُستخدم للتأكد من أن الملف يُستدعى داخل البيئة الرسمية. defined('ABSPATH') or exit; تعليم ووردبريس
Hooks نقاط تعليق برمجة تتيح للإضافات والقوالب التنصت والتفاعل مع نواة ووردبريس دون التعديل على ملفات النظام الأساسية. add_action('init', 'my_func'); تعليم ووردبريس
Actions نوع من الـ Hooks يتيح تشغيل وظائف وكود إضافي عند أحداث زمنية معينة أثناء تحميل الصفحة. add_action('wp_enqueue_scripts', 'my_scripts'); تعليم ووردبريس
Filters نوع من الـ Hooks يتيح استقبال بيانات وتعديلها ثم إعادة تمريرها قبل حفظها أو عرضها في الشاشة. add_filter('the_content', 'my_custom_content'); تعليم ووردبريس
$wpdb الكائن العام في ووردبريس الذي يمثل طبقة تجريد قاعدة البيانات ويستبدل الاستعلامات المباشرة بدوال آمنة. global $wpdb; $wpdb->get_results(...); تعليم ووردبريس
Path Disclosure ثغرة أمنية تظهر عند حدوث خطأ قاتل يكشف للمستخدمين المسار الكامل للمجلدات على خادم الويب. C:\Users\Name\Local Sites\app\public\wp-content\... تعليم ووردبريس
OPcache تقنية تخزين مؤقت داخل محرك PHP تحفظ الكود المترجم (Bytecode) في الذاكرة لتسريع استدعاء الملفات. تُستخدم لتخفيف أثر كثرة استدعاء ملفات require_once في ووردبريس. تعليم ووردبريس

أسئلة المراجعة واختبار الذات (للامتحانات)

سؤال 1 (اختيار من متعدد) سهل

ما الغرض الرئيسي من استخدام الثابت ABSPATH في ملفات الإضافات؟

  • • تسريع استعلامات قاعدة البيانات
  • • حماية الملف من الوصول المباشر عبر المتصفح خارج بيئة ووردبريس
  • • تعديل محتوى المقالات قبل عرضها
  • • إنشاء جداول جديدة في قاعدة البيانات
✅ الإجابة النموذجية: حماية الملف من الوصول المباشر عبر المتصفح خارج بيئة ووردبريس

الشرح والمراجعة: يقوم فحص defined('ABSPATH') بالتأكد من أن الملف تم تحميله ضمن دورة إقلاع ووردبريس الرسمية لمنع حدوث أخطاء قاتلة وكشف مسارات السيرفر.

المصدر: تعليم ووردبريس
سؤال 2 (اختيار من متعدد) متوسط

ما الفرق الأساسي بين Actions و Filters في ووردبريس؟

  • • Actions تتصل بقاعدة البيانات مباشرة و Filters لا تتصل
  • • Actions تنفذ كوداً عند حدث معين، بينما Filters تعدل البيانات وتلزم بإرجاع قيمة
  • • Filters تعمل في لوحة التحكم فقط بينما Actions تعمل في الواجهة الأمامية
  • • لا يوجد أي فرق بينهما وهما مجرد أسماء متطابقة
✅ الإجابة النموذجية: Actions تنفذ كوداً عند حدث معين، بينما Filters تعدل البيانات وتلزم بإرجاع قيمة

الشرح والمراجعة: الـ Actions تُستخدم لإضافة سلوك أو وظيفة جديدة، أما الـ Filters فتستقبل قيمة وتعدلها ثم تعيدها عبر return.

سؤال 3 (اختيار من متعدد) سهل

  • • index.php
  • • wp-settings.php
  • • wp-config.php
  • • wp-blog-header.php
✅ الإجابة النموذجية: wp-config.php

الشرح والمراجعة: ملف wp-config.php يحتوي على إعدادات الموقع ويُعرّف الثابت ABSPATH ليحتوي على مسار المجلد الرئيسي.

المصدر: تعليم ووردبريس
سؤال 4 (اختيار من متعدد) متوسط

ما هو الملف الذي يُعتبر العصب البرمجي الرئيسي لإقلاع نظام ووردبريس وتحميل الـ Hooks والكائن $wpdb؟

  • • wp-load.php
  • • wp-settings.php
  • • wp-blog-header.php
  • • index.php
✅ الإجابة النموذجية: wp-settings.php

الشرح والمراجعة: يقوم wp-settings.php بتحميل جميع الدوال الأساسية، والإضافات المفعلة، والكائن $wpdb، والقالب النشط.

المصدر: تعليم ووردبريس
سؤال 5 (اختيار من متعدد) سهل

كيف نحصل على نتائج استعلام يرجع عدة صفوف (Multiple Rows) ككائنات من قاعدة البيانات باستخدام $wpdb؟

  • • $wpdb->get_var()
  • • $wpdb->get_row()
  • • $wpdb->get_results()
  • • $wpdb->query_all()
✅ الإجابة النموذجية: $wpdb->get_results()

الشرح والمراجعة: الدالة $wpdb->get_results() تُستخدم لجلب مصفوفة من الصفوف أو الكائنات من قاعدة البيانات.

المصدر: تعليم ووردبريس
سؤال 6 (اختيار من متعدد) متوسط

لماذا يفضل استخدام $wpdb->users بدلاً من كتابة 'wp_users' في استعلامات SQL؟

  • • لأن كتابة أسماء الجداول النصوصية تسبب خطأ سنتكس في PHP
  • • ضمان عمل الكود إذا قُدمت بادئة جداول مخصصة أثناء تثبيت ووردبريس
  • • لأن $wpdb تسسرع قراءة الجداول بنسبة 50%
  • • لتشفير أسماء المستخدمين في قاعدة البيانات
✅ الإجابة النموذجية: ضمان عمل الكود إذا قُدمت بادئة جداول مخصصة أثناء تثبيت ووردبريس

الشرح والمراجعة: استخدام خصائص $wpdb الديناميكية يجعل الكود مرناً ويتكيف مع أي بادئة جداول (Table Prefix) يختارها مدير الموقع.

المصدر: تعليم ووردبريس
سؤال 7 (سؤال مقالي) متوسط

ما الذي يحدث عند استدعاء دالة add_action() في ملف إضافة تم فتحه مباشرة عبر المتصفح بدون بيئة ووردبريس؟

✅ الإجابة النموذجية: يحدث خطأ قاتل Fatal Error: Call to undefined function add_action() وتتوقف البرمجية وتنكشف مسارات السيرفر.

الشرح والمراجعة: السبب أن دوال ووردبريس لم يتم تحميلها في ذاكرة PHP لأن الملف لم يمر بتسلسل إقلاع ووردبريس.

المصدر: تعليم ووردبريس
سؤال 8 (سؤال مقالي) سهل

اشرح باختصار فائدة الكلمة المفتاحية global قبل المتغير $wpdb داخل الدوال.

✅ الإجابة النموذجية: تسمح بالوصول للكائن العام $wpdb الذي تم إنشاؤه في نطاق الإقلاع العام للاستفادة من دواله داخل النطاق المحلي للدالة.

الشرح والمراجعة: في PHP لا تستطيع الدالة رؤية المتغيرات الخارجية إلا بإعلانها كـ global أو تمريرها كـ argument.

المصدر: تعليم ووردبريس
سؤال 9 (سؤال مقالي) صعب

ما هما التقنيتان المستخدمتان لمعالجة ثقل كثرة استدعاء ملفات PHP في ووردبريس؟

✅ الإجابة النموذجية: تقنية OPcache للتخزين المؤقت لـ PHP Bytecode، وتقنيات Object Caching مثل Redis أو Memcached.

الشرح والمراجعة: تساعد هذه التقنيات على قراءة الكود والبيانات من الذاكرة الفائقة مباشرة دون الحاجة لمعالجة الكود أو إعادة الاستعلام.

المصدر: تعليم ووردبريس
سؤال 10 (سؤال مقالي) متوسط

اذكر أول ملفين يتم استدعاؤهما عند طلب صفحة رئيسية في ووردبريس بالترتيب.

✅ الإجابة النموذجية: الملف الأول هو index.php ثم يستدعي ملف wp-blog-header.php.

الشرح والمراجعة: تبدأ نقطة الدخول من index.php وتنتقل فوراً إلى wp-blog-header.php الذي يبدأ بتنسيق عملية الإقلاع.

المصدر: تعليم ووردبريس
سؤال 11 (سؤال مقالي) صعب

ما هو الخطر الأمني الرئيسي الناتج عن إظهار رسائل الأخطاء القاتلة على السيرفر (Path Disclosure)؟

✅ الإجابة النموذجية: كشف المسارات الكاملة للمجلدات وهيكلية السيرفر للمخترقين مما يساعدهم في استهداف الثغرات.

الشرح والمراجعة: عرض المسارات المطلقة مثل C:\Users\... يعطي المخترق معلومات حساسة عن بيئة الاستضافة.

المصدر: تعليم ووردبريس
سؤال 12 (سؤال مقالي) متوسط

ما هي الدالة المستخدمة في $wpdb لتأمين الاستعلامات والوقاية من ثغرات SQL Injection؟

✅ الإجابة النموذجية: الدالة $wpdb->prepare()

الشرح والمراجعة: تُستخدم prepare لتجهيز القيم وتنظيفها قبل دمجها في استعلام SQL.
