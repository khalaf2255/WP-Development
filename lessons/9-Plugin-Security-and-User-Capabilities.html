الدرس 01 | قسم Plugin Security

العقلية الأمنية وفحص صلاحيات المستخدمين (Security & Capabilities)

تأسيس العقلية الأمنية، قاعدة عدم الثقة بأي بيانات، وفحص صلاحيات الأدوار بـ current_user_can.

1. بناء العقلية الأمنية (Developing a Security Mindset)

تهانينا، كودك يعمل! ولكن هل هو آمن؟ ونظراً لأن الإضافات والقوالب تعمل عبر آلاف المواقع، فإنها تمثل الهدف الأكثر استهدافاً من الثغرات في ووردبريس.

🚨 المبدأ الأول والأهم: لا تضع ثقتك في أي بيانات (Never Trust Any Data)! لا تقم أبداً بالثوق في المدخلات الواردة من المستخدم، ولا البيانات القادمة من واجهات 3rd-party APIs، بل وحتى البيانات المخزنة داخل قاعدة بياناتك الخاصة! يجب التحقق والتعقيم دائماً.

القواعد التوجيهية الأربع (Guiding Principles)

  1. عدم الثقة مطلقاً: أي مدخل غير مفحوص هو ثغرة محتملة.
  2. الهروب المتأخر جداً (Escape as late as possible): قم بتطهير وهروب المخرجات فوراً لحظة طباعتها بـ echo.
  3. التدرج الهرمي للصلاحيات: لا تُنفذ الأوامر الحساسة إلا بعد التأكد من صلاحية المستخدم.
  4. التحقق والرفض أفضل من مجرد التعقيم: الـ Validation أضمن وأقوى من الـ Sanitization مجرداً.

2. أدوار وصلاحيات المستخدمين (User Roles & Capabilities)

كل مستخدم مسجل في ووردبريس ينتمي إلى **دور (User Role)** معين (مثل Administrator, Editor, Author, Subscriber). ينطوي كل دور على مجموعة من **الصلاحيات (Capabilities)** المحددة سلفاً (مثل manage_options للمسؤول أو edit_others_posts للمحرر).

الدور (Role) الصلاحية الشهيرة (Capability) الوصف والإمكانية السماحية
Administrator manage_options التحكم الكامل في الخيارات وتعديل إعدادات الموقع والإضافات.
Editor edit_others_posts تحرير وإدارة ونقل مقالات المستخدمين الآخرين لسلة المهملات.
Author publish_posts كتابة ونشر المقالات الخاصة بالمؤلف فقط.
Subscriber read قراءة المحتوى فقط دون أي صلاحيات تعديل أو إدارة.

3. تطبيق عملي: ثغرة رابط الحذف وبناء الحماية بـ current_user_can()

الكود الضعيف والمخترق (Unrestricted Vulnerable Code)

الكود التالي يُنشئ رابطاً لحذف المقال في الواجهة الأمامية، ولكن دون فحص صلاحيات المستخدم! يمكن لأي زائر غير مسجل الضغط على الرابط ونقل المقالات للـ Trash!

vulnerable-delete-link.php
<?php
// ❌ كود خطير: يسمح لأي زائر بحذف المقال دون فحص صلاحياته!
function wporg_delete_post() {
    if ( isset( $_GET['action'] ) && 'wporg_frontend_delete' === $_GET['action'] ) {
        $post_id = isset( $_GET['post'] ) ? (int) $_GET['post'] : null;
        if ( ! empty( $post_id ) ) {
            wp_trash_post( $post_id ); // كارثة أمنية!
            wp_safe_redirect( admin_url( 'edit.php' ) );
            exit;
        }
    }
}
add_action( 'init', 'wporg_delete_post' );

الكود الآمن المحمي (Restricted with current_user_can)

لحظر الزوار والمشتركين ومنح الصلاحية للمحرر والمسؤول فقط، نغلف الـ Filter والـ Action بالفحص القياسي current_user_can('edit_others_posts'):

secure-delete-link.php
<?php
// ✅ كود آمن: لا يُنفذ إلا إذا كان المستخدم يملك صلاحية edit_others_posts
function wporg_add_delete_post_ability() {
    if ( current_user_can( 'edit_others_posts' ) ) {
        add_filter( 'the_content', 'wporg_generate_delete_link' );
        add_action( 'init', 'wporg_delete_post' );
    }
}
add_action( 'plugins_loaded', 'wporg_add_delete_post_ability' );
