ترويسة الإضافة والتوثيق (Header Requirements & PHPDoc)

تفكيك Plugin DocBlock والحقول الـ 14، والفرق الجوهري بين هيدر ووردبريس وتوسيم التوثيق @package، وإدارة الإصدارات بـ @since.

1. الحد الأدنى الإجباري (Minimum Fields)

لكي يتعرف ووردبريس على ملف PHP كـ إضافة، يلزم وجود حقل إجباري واحد فقط في تعليق الترويسة وهو Plugin Name:

minimum-header.php
<?php
/*
 * Plugin Name: MY PLUGIN NAME
 */

2. تفكيك الحقول الـ 14 المتاحة (Available Header Fields)

فيما يلي النموذج البرمجي الكامل الذي يضم **جميع الحقول الـ 14 المتاحة في ترويسة ووردبريس الرسمية** مرتبة وموضحة داخل الكود قبل تفكيكها في الجدول التالي:

full-14-header-fields.php
<?php
/**
 * التوثيق البرمجي للملف (PHPDoc Block & @package Types)
 *
 * @package    My_Comprehensive_Plugin
 * @subpackage Includes/Admin
 * @author     Developer Name <developer@example.com>
 * @copyright  2026 Developer Name
 * @license    GPL-2.0-or-later
 * @version    1.0.0
 * @since      1.0.0
 */

/*
 * ترويسة إضافة ووردبريس (WordPress Plugin Header - 14 Fields)
 *
 * Plugin Name:       My Comprehensive Plugin
 * Plugin URI:        https://example.com/plugins/my-plugin/
 * Description:       A complete example demonstrating all 14 WordPress plugin header fields.
 * Version:           1.0.0
 * Requires at least: 6.0
 * Requires PHP:      7.4
 * Author:            Developer Name
 * Author URI:        https://example.com/
 * License:           GPL v2 or later
 * License URI:       https://www.gnu.org/licenses/gpl-2.0.html
 * Text Domain:       my-plugin
 * Domain Path:       /languages
 * Network:           false
 * Update URI:        https://example.com/my-plugin/
 * Requires Plugins:  woocommerce
 */
اسم الحقل (Header Field) حالة الحقل الوصف والاستخدام التقني
Plugin Name إجباري (Required) اسم الإضافة الذي يظهر في قائمة الإضافات في لوحة التحكم.
Plugin URI اختياري صفحة الإضافة الرئيسية (يُمنع استخدام رابط wordpress.org هنا).
Description اختياري وصف كافٍ ومختصر للإضافة (يفضل أقل من 140 حرفاً).
Version اختياري رقم الإصدار الحالي للإضافة ككل (مثل 1.7.2).
Requires at least موصى به أدنى إصدار لووردبريس تتوافق معه الإضافة (مثل 5.2).
Requires PHP موصى به أدنى إصدار لـ PHP مطلوب لتشغيل الإضافة (مثل 7.2).
Author اختياري اسم المطور أو المطورين (يفصل بينهم بفاصلة).
Author URI اختياري رابط موقع المطور أو صفحته الشخصية.
License موصى به الاسم المختصر لرخصة الإضافة (مثل GPLv2).
License URI اختياري رابط النص الكامل للرخصة.
Text Domain مهم للترجمة معرف الترجمة الخاص بالإضافة لاستخدامه مع gettext.
Domain Path اختياري مسار مجلد ملفات الترجمة (مثل /languages).
Network اختياري تحديد ما إذا كانت الإضافة تُفعل على مستوى الشبكة فقط (true).
Update URI حماية أمنية يمنع استبدال الإضافات الخاصة بتحديثات إضافة بنفس الاسم من دليلك الرسمي.
Requires Plugins حقل جديد (WP 6.5) قائمة التبعيات (Slugs) للإضافات الأخرى المطلوبة لتشغيل هذه الإضافة.

3. معنـى @package والفرق الجوهري بين التوثيق وهيدر الإضافة

في لغة PHP ونظام ووردبريس، يُعتبر الوسم @package أحد وسوم التوثيق القياسية (PHPDoc Tags). بالرغم من أنهما يظهران أعلى الملف داخل تعليقات، إلا أن الوظيفة والهدف منهما مختلفان تماماً:

وجه المقارنة هيدر الإضافة (Plugin Header Header) وسوم التوثيق (PHPDoc Header)
الكود النموذجي Plugin Name: Hello Dolly
Version: 1.7.2		 /** @package Hello_Dolly */
/** @version 1.7.2 */
المستهدف الأساسي نظام ووردبريس نفسه (WordPress Core) المطورون وأدوات التوثيق التلقائية
مكان الظهور لوحة تحكم ووردبريس (صفحة الإضافات / Plugins) داخل محرر الأكواد وقارئ الملفات فقط
درجة الإلزامية إجباري لتتعرف المنصة على الإضافة اختياري (معيار قياسي من أفضل الممارسات)
آلية العمل يقرأه ووردبريس برمجياً لإظهار التفعيل، الوصف، والتحديثات تتجاهله نواة ووردبريس تماماً، وتقرأه أدوات مثل phpDocumentor لتوليد التوثيق

أهمية الوسم @package برمجياً:

  • التوثيق التلقائي (Automated Documentation): تقرأ أدوات التوثيق مثل PHPDocumentor هذا الوسم لتجميع وتصنيف كافة الملفات والكلاسات التابعة لنفس المشروع تحت مجلد واحد.
  • تنظيم المشاريع الضخمة: يساعد المطورين في المشاريع ذات المئات من الملفات على معرفة التبعية البرمجية لكل ملف فور فتحه.
  • معايير ووردبريس القياسية (WordPress Coding Standards): تشترط معايير WPCS وجود الوسم لتأكيد احترافية وتوحيد نمط الكود.

4. اختـلاف رقم إصدار الإضافة عن رقم إصدار التوثيق والحل الذهبي بـ @since

هل يمكن أن يختلف رقم إصدار الإضافة (Version: 1.8.0) عن رقم الإصدار في تعليقات التوثيق (@version 1.5.0)؟ نعم، وبشدة!

لماذا وكيف يحدث هذا الاختلاف؟

يعود السبب لاختلاف النطاق (Scope) الذي يعبر عنه كل إصدار:

أ. إصدار الإضافة ككُل (Plugin Version)

يمثل حالة المشروع بأكمله كما يراه المستخدم في لوحة التحكم. عند إطلاق تحديث للإضافة (مثلاً إصلاح ثغرة أو إضافة ميزة)، يتغير الرقم في الهيدر الرئيسي إلى Version: 1.8.0.

ب. إصدار الملف التوثيقي (PHPDoc @version)

يمثل تاريخ آخر تعديل تم على هذا الملف أو الكلاس المحدد. إذا تم تحديث الإضافة لـ 1.8.0 ولكن هذا الملف لم يُمس منذ الإصدار 1.5.0، يظل التوثيق @version 1.5.0.

سيناريو عملي توضيحي:

Plugin Structure
my-plugin/
├── my-plugin.php       (الملف الرئيسي - Version: 1.1.0)
└── includes/
    ├── class-admin.php (تم تعديله - @version 1.1.0)
    └── class-api.php   (لم يتغير - @version 1.0.0)
💡 الحل الذهبي والمعيار الأفضل في ووردبريس: استخدام الوسم @since
لتجنب اللبس الناتج عن متابعة تغيير أرقام الملفات مع كل إصدار، يفضل مطورو ووردبريس استخدام الوسم @since 1.2.0 والذي يعني: "تم إنشاء أو إضافة هذا الملف لأول مرة في إصدار الإضافة رقم 1.2.0". بهذه الطريقة لا تحتاج لتغيير رقم التوثيق في كل ملف عند التحديث!
⚠️ ملاحظة هامة حول مقارنة رقم الإصدار (Version Comparison Note): يستخدم ووردبريس الدالة القياسية في PHP المسماة version_compare() لمقارنة أرقام إصدار الإضافة مع التحديثات. تأكد دائماً أن رقم الإصدار الجديد يعتبر "أكبر" حسابياً في PHP. على سبيل المثال: الإصدار 1.02 يعتبر في PHP أكبر حسابياً من الإصدار 1.1!

5. إضافة روابط إجراءات تخصيصية بجوار رابط التفعيل (Plugin Action Links)

عند عرض الإضافة في صفحة الإضافات (plugins.php) في لوحة التحكم، يتيح لك ووردبريس إضافة روابط تخصيصية مفيدة للمستخدم مثل رابط "الإعدادات" (Settings) أو "التعليمات" (Docs) بجوار روابط التفعيل والتعطيل الافتراضية:

plugin-action-links.php
<?php
// 1. ربط الفلتر الديناميكي بالمستنـد الرئيسي للإضافة
add_filter( 'plugin_action_links_' . plugin_basename( __FILE__ ), 'my_plugin_add_action_links' );

function my_plugin_add_action_links( $links ) {
    
    // 2. إنشاء الروابط الخاصة بك بنصوص قابلة للترجمة
    $settings_link = '<a href="admin.php?page=my-plugin-settings">' . __( 'Settings', 'textdomain' ) . '</a>';
    $docs_link     = '<a href="https://example.com/docs" target="_blank">' . __( 'Docs', 'textdomain' ) . '</a>';

    // 3. إضافة الروابط الجديدة في مصفوفة الروابط
    array_push( $links, $settings_link, $docs_link );

    // 4. إرجاع المصفوفة المحدثة (طبيعة عمل الـ Filter كما تعلمنا!)
    return $links;
}

تفكيك أجزاء الفانكشن والفلتر المستخدم (Line-by-Line Breakdown):

  • plugin_action_links_{$plugin_file}: خطاف فلتر ديناميكي (Dynamic Filter Hook). يتم استدعاؤه بواسطة نواة ووردبريس لكل إضافة في الجدول، حيث يتم دمجه باسم مسار الإضافة الرئيسي لتحديد الإضافة بدقة دون التأثير على بقية الإضافات.
  • plugin_basename(__FILE__): دالة في ووردبريس تُعيد المسار النسبي لملف الإضافة الرئيسي (مثال: my-plugin/my-plugin.php)، مما يضمن تشغيل الفلتر حصرياً على صف إضافتك أنت.
  • $links: مصفوفة تحتوي على الروابط الـ HTML الحالية الخاصة بالإضافة الممررة من ووردبريس (مثل روابط Deactivate / Activate).
  • __('Settings', 'textdomain'): دالة الترجمة التدويلية (Internationalization) التي تضمن إمكانية ترجمة كلمة Settings إلى أي لغة بناءً على حقل Text Domain الخاص بالإضافة.
  • array_push($links, ...): دالة في PHP لإضافة العناصر الجديدة إلى نهاية المصفوفة. (ملاحظة: إذا أردت ظهور رابط الإعدادات في بداية الروابط قبل Deactivate، يمكنك استخدام array_unshift() بدلاً منها).
  • return $links;: إرجاع المصفوفة المعدلة إجبارياً لإكمال عقد عمل الفلتر (Filter Contract)، وبدونها لن تظهر أي روابط.
