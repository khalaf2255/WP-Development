تاريخ الإنشاء: ٢‏/٨‏/٢٠٢٦
نظرة عامة: يقدم هذا الدليل دراسة أكاديمية شاملة لمفهوم إضافات ووردبريس (WordPress Plugins) وكيفية توسيع وظائف النظام الأساسي (WordPress Core) دون المساس بكوده الأصلي. يتناول الدليل المكونات البرمجية للإضافة بدءاً من لغة PHP والأصول المساعدة مثل CSS وJavaScript، وصولاً إلى الحد الأدنى لتشغيل الإضافة عبر رأس الإضافة (Plugin Header / DocBlock). كما يشرح الدليل تدرج الإضافات في التعقيد وطريقة توزيعها عبر مستودع ووردبريس الرسمي.
✨ ترتيب النصوص والمواضيع: تم ترتيب المادة العلمية منطقياً بالبدء بالمفاهيم الأساسية وتعرّف ماهية الإضافات، ثم التدرج نحو البنية الهيكلية والحد الأدنى المتطلب لتشغيلها، يلي ذلك عرض مستويات التعقيد البرمجي عبر أمثلة عملية، وانتهت بالمعايير الخاصة بنشر وتوزيع الإضافات على المستودع الرسمي.

1. ## ١. المفهوم الأساسي والبنية الهيكلية لإضافات ووردبريس

تعليم ووردبريس

١. المفهوم الأساسي والبنية الهيكلية لإضافات ووردبريس

١.١ ماهية الإضافة وتأثيرها على النواة

تُعرف الإضافة (Plugin) في بيئة ووردبريس بأنها حزمة برمجية مستقلة (Software Package) تهدف إلى توسيع وإضافة وظائف جديدة للنظام الأساسي (WordPress Core) دون الحاجة لتعديل الشفرة البرمجية المصدرية للنواة. يضمن هذا النهج عدم ضياع التعديلات عند التحديث المستقبلي للنظام.

> 💡 ملاحظة للمذاكرة: التعديل المباشر على نواة ووردبريس يُعد خطأً برمجياً جسيماً؛ الإضافات هي الوسيلة الآمنة والمعتمدة رسمياً للتوسعة البرمجية.

١.٢ المكونات والأصول البرمجية للإضافة

تتكون الإضافة الحديثة من مجموعة متكاملة من التقنيات والأصول (Assets):

- لغة PHP (Hypertext Preprocessor): المكون الرئيسي واللغة الأساسية التي تُكتب بها منطق الإضافة (Business Logic) والتفاعل مع قاعدة البيانات.
- أوراق الأنماط المتتالية (CSS - Cascading Style Sheets): تُستخدم للتحكم في المظهر البصري والتنسيقات الخاصة بالإضافة سواء في الواجهة الأمامية (Frontend) أو لوحة التحكم (Admin Dashboard).
- لغة جافا سكريبت (JavaScript): تُستخدم لإضافة التفاعلية الديناميكية، ومعالجة الطلبات في الخلفية دون إعادة تحميل الصفحة (AJAX).
- الوسائط والصور (Images & Assets): الأيقونات والتصميمات الرسومية التوضيحية الخاصة بالإضافة.

| المكون التقني | لغة البرمجة / التقنية | الوظيفة الرئيسية في الإضافة |
| :--- | :--- | :--- |
| المنطق البرمجي (Logic) | PHP | معالجة البيانات، الربط مع خطاطيف ووردبريس (Hooks) والقواعد البيانات |
| التنسيق البصري (Styling) | CSS | تصميم الواجهات، ضبط الألوان والأبعاد في لوحة التحكم والواجهة |
| التفاعلية (Interactivity) | JavaScript | إضافة السلوك الديناميكي، الاتصالات غير التزامنية (AJAX/Fetch) |
| الأصول (Assets) | Media / Images | تحسين تجربة المستخدم البصرية وتوفير الأيقونات |

تعليم ووردبريس

٢. الحد الأدنى للتكوين الهيكلي وأمثلة التطبيق

٢.١ رأس الإضافة (Plugin Header / DocBlock)

رغم أن الإضافات المتقدمة قد تحتوي على مئات الملفات والمجلدات، إلا أن الحد الأدنى المطلوب برمجياً لتشغيل أي إضافة هو ملف PHP واحد يحتوي في بدايته على كتلة تعليق توثيقية مخصصة تُعرف بـ رأس الإضافة (Plugin Header) أو (DocBlock).

```php
/
* Plugin Name: My Custom Plugin
* Plugin URI: https://example.com/my-plugin
* Description: إضافة مخصصة لتوسيع وظائف ووردبريس.
* Version: 1.0.0
* Author: Developer Name
* Author URI: https://example.com
* License: GPL2
*/

// منع الوصول المباشر للملف للأمان
if (!defined('ABSPATH')) {
exit;
}
```

> ⚠️ تنبيه امتحاني هام: يقرأ نظام ووردبريس رأس الإضافة (DocBlock) عند مسح مجلد `wp-content/plugins`؛ وبدونه لن يستطيع النظام التعرف على الإضافة أو تفعيلها في لوحة التحكم.

٢.٢ دراسة حالة: إضافة هالو دولي (Hello Dolly)

تُعد إضافة هالو دولي (Hello Dolly) من أوائل الإضافات التاريخية في ووردبريس، وتُستخدم كنموذج إرشادي بسيط للبنية البرمجية:

- حجم الكود: يتكون الملف من قرابة 100 سطر برمي فقط في ملف واحد.
- الوظيفة: عرض كلمات من أغنية شهيرة بشكل عشوائي في أعلى لوحة تحكم الأدمن.
- البنية البرمجية: تدمج بين كود PHP لاستخراج الكلمات وتنسيقات CSS مصغرة للتحكم في مظهر النص العلوي.

3. ## ٣. مستويات التعقيد ونشر الإضافات على المستودع الرسمي

تعليم ووردبريس

٣. مستويات التعقيد ونشر الإضافات على المستودع الرسمي

٣.١ نطاق وتدرج الإضافات (Scope & Complexity)

تتدرج الإضافات في تعقيدها البرمجي بناءً على المتطلبات الوظيفية للمشروع:

- الإضافات البسيطة (Simple Plugins): مثل إضافة تقوم بجمع وتتبع أحدث 10 مقالات وعرض روابطها في شريط جانبي.
- الأنظمة البرمجية المكتملة (Complex Systems): مثل بناء نظام تذاكر الدعم الفني (Support Ticketing System) الكامل الذي يتضمن:
- أنواع المقالات المخصصة (Custom Post Types): لإنشاء وإدارة التذاكر ككيانات مستقلة.
- الحالات المخصصة (Custom Statuses): مثل (مفتوحة، قيد المعالجة، مغلقة).
- نظام التنبيهات عبر البريد الإلكتروني (Email Notifications): لإشعارات العميل والفريق الفني.
- بوابة العميل (Client Portal): واجهة أمامية مخصصة للعملاء لمتابعة التذاكر.

٣.٢ النشر والتوزيع في دليل ووردبريس (WordPress.org Directory)

عند تطوير الإضافة وفق معايير التوثيق وجودة الكود القياسية، يتاح للمطور نشرها في مستودع إضافات ووردبريس الرسمي (WordPress.org Plugin Directory)، مما يتيح:

1. وصول الإضافة لملايين المستخدمين حول العالم.
2. إمكانية الحصول على التحديثات التلقائية والتغذية الراجعة من مجتمع المطورين.
3. بناء سمعة برمجية للمطور والمساهمة في بيئة المصدر المفتوح.

العلاقة بين نواة ووردبريس والإضافة البرمجية

تكامل وإضافة

تكمل الإضافة وظائف النواة الأساسية بدون التعديل المباشر عليها، مما يحافظ على استقرار النظام وموثوقية التحديثات.

💡 خلاصة الربط والامتحان:

الإضافة تمتد فوق النواة لتوفير وظائف إضافية دون كسر كود النظام الأصلي.

الحد الأدنى للملف الواحد مقابل الأنظمة البرمجية المتقدمة

تطور أو تسلسل

تبدأ الإضافة بملف PHP واحد يحمل الترويسة التوثيقية (DocBlock)، وتتطور لتصبح نظاماً كبيراً يضم أنماط مقالات مخصصة وبوابات عملاء.

💡 خلاصة الربط والامتحان:

الشرط الأساسي لتسجيل الإضافة ثابت بغض النظر عن حجم الإضافة وتعدد ملفاتها.
