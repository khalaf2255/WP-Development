أساسيات الإضافة وبداية الإنشاء (Getting Started & Overview)

خطوات إنشاء مجلد الإضافة عبر الترمينال، آليات الكشف في لوحة التحكم، والتعريف الشامل بـ Core APIs النواة.

1. خطوات بدء إنشاء إضافة جديدة (Getting Started)

في أبسط صورها، إضافة ووردبريس هي مجرد ملف PHP يحتوي على تعليق ترويسة مخصص. التوصية القياسية هي إنشاء مجلد مخصص باسم الإضافة داخل مجلد wp-content/plugins لجمع كافة ملفات الإضافة في مكان واحد منسق.

خطوات الإنشاء الإجرائية (Execution Steps)

  1. الانتقال إلى مجلد wp-content داخل تثبيت ووردبريس.
  2. فتح مجلد plugins.
  3. إنشاء مجلد جديد وتسميته بحروف صغيرة وشرطات نسبيّة (Slug) مثل: my-plugin-name.
  4. إنشاء ملف PHP رئيسي داخل المجلد بنفس الاسم: my-plugin-name.php.
  5. إضافة تعليق ترويسة الإضافة (Plugin Header Comment) في بداية الملف.
Unix Command Line Terminal
# الانتقال لمجلد الإضافات وإنشاء المجلد والملف
wordpress $ cd wp-content/plugins
plugins $ mkdir my-plugin-name
plugins $ cd my-plugin-name
my-plugin-name $ touch my-plugin-name.php

2. كيف يكتشف ووردبريس الإضافات؟ (How WordPress Loads Plugins)

عندما يفتح المسؤول صفحة **الإضافات (Plugins)** في لوحة تحكم ووردبريس، يقوم النظام بمسح (Scan) المجلد wp-content/plugins وكافة المجلدات الفرعية التابعة له للبحث عن ملفات PHP تحتوي على **تعليق ترويسة الإضافة (Header Comment)**.

📌 قاعدة الملف المنفرد للترويسة: إذا كانت الإضافة تتكون من عدة ملفات PHP، يجب أن يتضمن **ملف واحد فقط** تعليق ترويسة الإضافة (الملف الرئيسي). لا تضع ترويسة إضافة في الملفات المساعدة الداخليّة لمنع ووردبريس من قراءتها كإضافات متعددة متضاربة!

3. واجهات برمجة التطبيقات بالنواة (WordPress Core APIs)

تُعد واجهات برمجة التطبيقات بالنواة (WordPress Core APIs) الحجر الأساسي لتطوير الإضافات والقوالب في ووردبريس. الهدف الرئيسي منها هو تقديم أساليب قياسية وآمنة للتعامل مع المهام الشائعة، مما يغنيك عن كتابة أكواد معقدة من الصفر (أو إعادة اختراع العجلة):

أ. Options API (إدارة الإعدادات والخيارات)

تُستخدم هذه الواجهة لتخزين، قراءة، وتحديث البيانات في قاعدة بيانات ووردبريس (تحديداً في جدول wp_options). وهي مثالية لحفظ إعدادات إضافتك، مثل لون معين اختاره المستخدم، أو مفتاح API، أو حالة خيار معين (تفعيل/تعطيل).

  • get_option($option_name): لجلب قيمة خيار معين من قاعدة البيانات.
  • update_option($option_name, $new_value): لتحديث قيمة خيار (أو إنشائه إذا لم يكن موجوداً).
  • add_option($option_name, $value): لإضافة خيار جديد فقط إذا لم يكن مخزناً من قبل.
  • delete_option($option_name): لحذف الخيار نهائياً من قاعدة البيانات.
options-api-example.php
<?php
// 1. حفظ خيار في قاعدة البيانات (أو تحديثه)
update_option( 'my_plugin_theme_color', 'blue' );

// 2. استرجاع القيمة في مكان آخر داخل الكود (مع قيمة افتراضية 'default_red')
$color = get_option( 'my_plugin_theme_color', 'default_red' );

echo $color; // المخرج: blue

ب. HTTP API (إجراء الطلبات الشبكية)

بدلاً من كتابة كود cURL طويل ومعقد أو الاعتماد على مكتبات مثل file_get_contents (التي قد تكون معطلة على بعض الاستضافات لعدم حمايتها)، توفر هذه الواجهة طريقة موحدة وآمنة لإرسال واستقبال البيانات من خوادم خارجية (مواقع أخرى أو APIs خارجية):

  • wp_remote_get($url): لطلب بيانات من موقع خارجي عبر (GET Request).
  • wp_remote_post($url, $args): لإرسال بيانات إلى موقع خارجي عبر (POST Request).
  • wp_remote_retrieve_body($response): لاستخراج نص الاستجابة المقروء فقط من الرد.
http-api-example.php
<?php
// إرسال طلب GET إلى API خارجي
$response = wp_remote_get( 'https://api.example.com/data' );

// التأكد من عدم وجود خطأ في الاتصال بواسطة is_wp_error
if ( ! is_wp_error( $response ) ) {
    // استخراج نص الاستجابة (عادة ما يكون بتنسيق JSON)
    $body = wp_remote_retrieve_body( $response );
    $data = json_decode( $body );
}

ج. Plugin API (إدارة الأحداث والخطافات - Hooks)

هذه الواجهة هي **"قلب ووردبريس النابض"**. تسمح للمطورين بالربط مع دورة حياة ووردبريس، إما لتنفيذ كود معين عند حدث محدد، أو لتعديل وتصفية البيانات قبل عرضها. تُقسم إلى نوعين أساسيين:

  • الأفعال (Actions): لتنفيذ وظيفة ما في وقت معين (مثلاً: إرسال بريد إلكتروني عند نشر مقال جديد).
  • الفلاتر (Filters): لتعديل نص أو بيانات قبل معالجتها أو عرضها على الشاشة (مثل دالة wptexturize).
  • add_action($hook_name, $callback_function): لربط دالتك بحدث معين.
  • add_filter($hook_name, $callback_function): لربط دالتك بفلتر لتعديل بيانات.
  • do_action($hook_name): لإنشاء خطاف حدث جديد خاص بإضافتك.
  • apply_filters($hook_name, $value): لإنشاء خطاف فلتر جديد خاص بإضافتك.
plugin-api-filter-example.php
<?php
// مثال على Filter الجاهز للنواة: إضافة نص تلقائي في نهاية كل مقال منفرد
function add_footer_to_content( $content ) {
    if ( is_single() ) {
        $content .= '<p>شكراً لقراءة المقال!</p>';
    }
    return $content;
}
add_filter( 'the_content', 'add_footer_to_content' );

مثال عملي تطبيقي للربط بين apply_filters و add_filter (حساب أسعار العيادة):

في هذا المثال، توفر إضافة حجز العيادة دالة لحساب السعر مع إتاحة خطافات الفلاتر apply_filters لتعديل السعر والنص، بينما تقوم دوال الفلتر المستقلة بخصم 20% للأطفال وتعديل النص المطبوع عبر add_filter مع تحديد الأولوية 20:

clinic-appointment-price-filters.php
<?php
// 1. دالة حساب سعر الكشف وتمرير البيانات عبر الخطافات apply_filters
function get_final_appointment_price( $base_price, $textBeforePrice = "السعر النهائي بعد الخصم والضريبة هو: " ) {

    // يمر السعر والنص هنا لإتاحة تعديلهما بواسطة أي add_filter يعترض الطريق
    $final_price     = apply_filters( 'calculate_clinic_price', $base_price );
    $textBeforePrice = apply_filters( 'calculate_clinic_textBeforePrice', $textBeforePrice );

    return $textBeforePrice . $final_price;
}

// 2. استدعاء الدالة بسعر أساسي 100 (قبل تسجيل الفلاتر)
echo get_final_appointment_price( 100 ) . "<br>";

// 3. دالة خصم الأطفال (أخذ السعر الجديد، وخصم 20% منه)
function apply_kids_discount( $price ) {
    return $price - ( $price * 0.20 );
}

// 4. دالة تعديل نص ما قبل السعر
function apply_kids_discountX( $textBeforePrice ) {
    return $textBeforePrice;
}

// 5. تسجيل الدوال بالخطافات عبر add_filter (الأولوية 20 لتعمل بعد معالجة الضريبة)
add_filter( 'calculate_clinic_price', 'apply_kids_discount', 20 );
add_filter( 'calculate_clinic_textBeforePrice', 'apply_kids_discountX', 20 );

// 6. السعر الأساسي للخدمة هو 100 مع نص مخصص
$price_to_pay = get_final_appointment_price( 100, "السعر النهائي بعد الفلتر: " );

echo $price_to_pay;
✨ خلاصة فوائد استخدام Core APIs:
  1. الأمان والحماية: دوال Core APIs تُراعي معايير الأمان وتُعالج البيانات تلقائياً ضد الثغرات.
  2. التوافقية (Compatibility): تضمن أن كودك سيعمل على مختلف أنواع الاستضافات وبغض النظر عن إعدادات السيرفر.
  3. النظافة والإنتاجية: اختصار عشرات أسطر الكود المعقدة إلى دالة واحدة بسيطة وواضحة.
