أفضل الممارسات ومنع تضارب الأسماء (Best Practices & Naming Collisions)

تقنيات البادئات (Prefixing)، النطاقات (Namespaces)، التخزين المؤقت (Transients)، البرمجة الكائنية (OOP)، والتحميل الشرطي.

1. منع تضارب الأسماء (Avoid Naming Collisions)

تُعتبر هذه القاعدة القانون الأول والأهم في تطوير إضافات وقوالب ووردبريس. يحدث تضارب الأسماء (Naming Collision) عندما تستخدم إضافتك نفس اسم المتغير أو الدالة أو الكلاس الذي تستخدمه إضافة أخرى على نفس الموقع أو نواة ووردبريس في الـ Global Scope.

💡 ما هي المشكلة في الأصل؟
لغة PHP في البرمجة الإجرائية لا تسمح بوجود دالتين أو كلاسين يحملان نفس الاسم بالضبط في النطاق العام. إذا قمت بإنشاء دالة باسم get_user_data()، وقام مطور إضافة أخرى على نفس الموقع بإنشاء دالة بنفس الاسم: سينهار الموقع فوراً ويظهر خطأ قاتل:
Fatal error: Cannot redeclare function get_user_data()

الطريقة الأولى: التسمية المسبوقة (Prefix Everything)

تعتمد الفكرة على اختيار بادئة فريدة مخصصة لإضافتك (عادة من 3 إلى 5 أحرف) ووضعها في بداية اسم كل عنصر تتيحه في الـ Global Scope. على سبيل المثال، إذا كانت إضافتك اسمها Kids Care Clinic، يمكنك اختيار البادئة: kcc_ أو kidscare_:

مقارنة شمولية لتطبيق البادئة الفريدة (Prefixing) على عناصر الكود المختلفة:

عنصر الكود (Code Element) ❌ طريقة سيئة (عرضة للتضارب والانهيار) ✅ طريقة صحيحة ومحمية (مزودة ببادئة kcc_)
1. الدوال (Functions) function save_settings() { ... } function kcc_save_settings() { ... }
2. الكلاسات (Classes & Traits) class Patient { ... } class KCC_Patient { ... }
3. المتغيرات العامة (Globals) $database_version = '1.0'; $kcc_database_version = '1.0';
4. مساحات الأسماء (Namespaces) namespace Core\Admin; namespace KidsCareClinic\Core\Admin;
5. خيارات DB (Options API) update_option( 'api_key', '12345' ); update_option( 'kcc_api_key', '12345' );
6. التخزين المؤقت (Transients) set_transient( 'recent_posts', $data ); set_transient( 'kcc_recent_posts', $data );
🚨 بادئات يُحظر استخدامها تماماً: بما أنك تطور جزءاً من منظومة ووردبريس، يُحظر استخدام البادئات الخاصة بالنواة مثل: wp_ أو WordPress أو __ (الشرطتان السفليتان). كما يُحظر استخدام بادئات الإضافات الشهيرة (مثل woo_ لمواصفات WooCommerce).

2. أسلوب البرمجة الكائنية والـ Namespaces (OOP & Namespaces)

الأسلوب الأحدث والأسهل لمنع تضارب الأسماء هو كبسولة كود الإضافة بالكامل داخل **Class** أو **Namespace** مع فحص وجود الكلاس أولاً بـ class_exists():

ما هو الـ Namespace؟ وكيف نستخدمه؟

الـ Namespace (مساحة الأسماء) هو أشبه بـ **"المجلدات الوهمية"** داخل الكود. في جهاز الكمبيوتر، لا يمكنك وضع ملفين باسم index.php داخل نفس المجلد، ولكن يمكنك وضع ملف باسم index.php في مجلد folder1 وملف آخر بنفس الاسم في مجلد folder2.

هذا بالضبط ما يفعله الـ Namespace في PHP! فهو يسمح لك بتسمية الكلاسات والدوال بأسماء عادية دون الخوف من تضارب الأسماء مع إضافات أخرى.

includes/class-settings.php (تعريف الـ Namespace)
<?php
namespace KidsCareClinic\Admin; // 1. تعريف المجلد الوهمي الخاص بإضافتك

class Settings {
    public function display() {
        echo "إعدادات عيادة الأطفال";
    }
}

طرق استدعاء الكلاس من مكان آخر:

plugin-main.php (استدعاء الكلاس)
<?php
// الطريقة الأولى (استخدام كلمة use - الأفضل والأسهل):
use KidsCareClinic\Admin\Settings;

$settings = new Settings();
$settings->display();

// الطريقة الثانية (الاسم الكامل المباشر):
$settings_direct = new \KidsCareClinic\Admin\Settings();
$settings_direct->display();

3. الـ Transients في ووردبريس وكيفية استخدامها (WordPress Transients)

ما هو الـ Transients؟ وكيف نستخدمه؟

الـ Transient في ووردبريس هو نوع من **التخزين المؤقت (Caching)** لبيانات خفيفة داخل قاعدة البيانات (في جدول wp_options) مع تحديد مدة صلاحية (Expiration Time) محددة بالثواني.

تستخدمه عندما يكون لديك عملية بطيئة أو ثقيلة (مثل جلب بيانات من API خارجي، أو تنفيذ استعلام معقد في قاعدة البيانات)، فتقوم بحفظ النتيجة مؤقتاً لمدة ساعتين مثلاً، بدلاً من إعادة جلبها مع كل زائر يفتح الصفحة مما يُسرّع الموقع ويخفف الضغط على السيرفر.

الدوال الـ 3 الأساسية للتعامل مع الـ Transients:

  1. set_transient($transient, $value, $expiration): لحفظ البيانات مؤقتاً وتحديد مدة الصلاحية بالثواني.
  2. get_transient($transient): لقراءة البيانات المخزنة مؤقتاً، وتُعيد false في حال عدم وجود البيانات أو انتهاء صلاحيتها.
  3. delete_transient($transient): لحذف البيانات المؤقتة يدوياً قبل انتهاء وقتها عند التحديث.
transients-example.php
<?php
// 1. محاولة قراءة البيانات المخزنة مؤقتاً
$cached_posts = get_transient( 'kcc_latest_posts' );

if ( false === $cached_posts ) {
    // البيانات غير موجودة أو انتهت صلاحيتها! جلبها من جديد من قاعدة البيانات أو الـ API
    $cached_posts = array( 'post1', 'post2' );

    // حفظ البيانات مؤقتاً لمدة ساعتين (2 * HOUR_IN_SECONDS)
    set_transient( 'kcc_latest_posts', $cached_posts, 2 * HOUR_IN_SECONDS );
}

// 2. استخدام البيانات الجاهزة فوراً دون إجهاد السيرفر
print_r( $cached_posts );

// 3. حذف التخزين المؤقت يدوياً عند تحديث المقالات
delete_transient( 'kcc_latest_posts' );
💡 الثوابت الزمنية الجاهزة في ووردبريس: توفر نواة ووردبريس ثوابت جاهزة للوقت لتسهيل تحديد المدة الزمنية: MINUTE_IN_SECONDS (60 ثانية)، HOUR_IN_SECONDS (3600 ثانية)، DAY_IN_SECONDS (86400 ثانية)، WEEK_IN_SECONDS، و YEAR_IN_SECONDS.

📊 جدول مقارنة وتلخيص سريع بين Namespace و Transients:

المفهوم (Concept) الهدف الأساسي منه متى وأين تستخدمه؟
Namespace تنظيم الكود ومنع تضارب أسماء الكلاسات والدوال في PHP. عند كتابة إضافات وقوالب باستخدام البرمجة الكائنية OOP أو الهيكلية الحديثة.
Transients تسريع الموقع عبر التخزين المؤقت للبيانات الثقيلة في قاعدة البيانات. عند إرسال طلبات لـ API خارجي أو تنفيذ استعلامات DB معقدة وبطيئة.

4. الهيكل المجلدي المنظم والتحميل الشرطي (Folder Structure & Conditional Loading)

يُنصح بجمع الملفات ذات الوظائف المتشابهة في مجلدات فرعية واضحة داخل جذر الإضافة:

Recommended Directory Tree
/plugin-name
├── plugin-name.php    # الملف الرئيسي بالترويسة
├── uninstall.php      # ملف التنظيف عند الحذف
├── /languages/        # ملفات الترجمة (.mo / .po)
├── /includes/         # كود PHP والـ Core Classes
├── /admin/            # كود لوحة التحكم والـ Assets الخاصة بالإدارة
│   ├── /css/
│   ├── /js/
│   └── /images/
└── /public/           # كود الواجهة الأمامية للمستثمر الزائر
    ├── /css/
    ├── /js/
    └── /images/

التحميل الشرطي الشامل ودوال الفحص الشرطي (WordPress Conditional Tags)

إلى جانب الدالة is_admin()، يوفر نظام ووردبريس مجموعة واسعة من **الدوال الشرطية (Conditional Tags)** التي تمكنك من التحكم الكامل في مكان وزمان تنفيذ أي كود برمجي (سواء في لوحة التحكم، أو الواجهة الأمامية، أو أثناء طلبات AJAX، أو المهام المجدولة الخفية).

1. التمييز بين البيئات والسياقات السيرفرية (Environment & Context Conditions)

أ. is_admin()

  • التعريف: تتحقق ممّا إذا كان الطلب الحالي يدور داخل صفحات لوحة التحكم الإدارية (wp-admin).
  • متى نستخدمها؟ لتحميل ملفات CSS/JS الخاصة بالإدارة فقط، أو منع تشغيل أكواد لوحة التحكم في الواجهة الأمامية للموقع لزيادة السرعة والأمان.
is-admin-example.php
<?php
if ( is_admin() ) {
    // كود يُنفذ فقط للمدير داخل لوحة التحكم wp-admin
    add_action( 'admin_menu', 'kcc_add_custom_menu' );
}

ب. wp_doing_ajax()

  • التعريف: تتحقق ممّا إذا كان الطلب الحالي عبارة عن طلب AJAX صامت في الخلفية.
  • متى نستخدمها؟ عندما تريد معالجة بيانات مرسلة عن بُعد دون إعادة تحميل الصفحة، وتجنب طباعة عناصر HTML عادية أثناء طلبات الـ AJAX.
doing-ajax-example.php
<?php
if ( wp_doing_ajax() ) {
    // تنفيذ استجابة سريعة لطلب Ajax
    add_action( 'wp_ajax_kcc_save_data', 'kcc_process_ajax' );
}

ج. wp_doing_cron()

  • التعريف: تتحقق ممّا إذا كان ووردبريس يقوم حالياً بتشغيل مهام مبرمجة في الخلفية (WP-Cron) (مثل إرسال النشرات البريدية المجدولة).
  • متى نستخدمها؟ لمنع تشغيل أكواد تفاعلية مخصصة للزائر أثناء تنفيذ المهام الخفية التلقائية وتخفيف الضغط على السيرفر.
doing-cron-example.php
<?php
if ( wp_doing_cron() ) {
    // كود خاص بتخفيف الحمل أثناء المهام المجدولة في الخلفية
    error_log( 'جاري تنفيذ مهام الصيانة المجدولة...' );
}

د. wp_is_json_request() أو REST_REQUEST

  • التعريف: تتحقق ممّا إذا كان الطلب القادم مستهدفاً لـ REST API الخاص بووردبريس.
  • متى نستخدمها؟ عند بناء تطبيقات موبايل أو ربط موقعك بأنظمة خارجية عبر API وتود تخصيص الاستجابة بتنسيق JSON فقط.
json-rest-example.php
<?php
if ( wp_is_json_request() ) {
    // تخصيص البيانات المرسلة عبر REST API وتصفية الهيدر
}

هـ. is_ssl() و is_multisite()

  • is_ssl(): تتحقق مما إذا كان الموقع يتصفح عبر اتصال مشفر آمن HTTPS، وتستخدم لتغيير روابط الموارد الخارجية لتبدأ بـ https://.
  • is_multisite(): تتحقق مما إذا كان الموقع يعمل بنظام الشبكة المتعددة (Multisite Network).

2. التحكم بناءً على صلاحيات وحالة المستخدمين (User & Capability Conditions)

أ. is_user_logged_in()

  • التعريف: تتحقق مما إذا كان الزائر مسجلاً لدخوله في الموقع أم مجرد زائر مجهول (Guest).
  • متى نستخدمها؟ لعرض محتوى حصري للأعضاء المسجلين أو إعادة توجيه الزوار لصفحة التسجيل.
logged-in-example.php
<?php
if ( is_user_logged_in() ) {
    echo "مرحباً بك مجدداً في عيادتنا!";
} else {
    echo "يرجى تسجيل الدخول لحجز موعد.";
}

ب. current_user_can( $capability )

  • التعريف: تتحقق ممّا إذا كان المستخدم الحالي يملك صلاحية معينة (تُسمى في ووردبريس بـ Capabilities)، والممنوحة لأدوار المستخدمين المختلفة (Administrator, Editor, Author, Contributor, Subscriber).
  • متى نستخدمها؟ لحماية الأمان الفعلي! لا تعتمد على is_admin() وحدها لحماية الأكواد والروابط الحساسة، بل استخدم دائماً current_user_can().
user-can-example.php
<?php
// التأكد من أن المستخدم مدير ويحق له تعديل الإعدادات
if ( current_user_can( 'manage_options' ) ) {
    // كود التعديل على قاعدة البيانات أو حفظ الإعدادات
}

📋 القائمة الشاملة والمصنّفة لأهم الصلاحيات الرسمية في ووردبريس:

1. إدارة النظام والإعدادات (Administrative & Settings Capabilities)

هذه الصلاحيات عادة ما يملكها المدير (Administrator) فقط لحماية نواة وإعدادات الموقع:

الصلاحية (Capability) الدور المعتاد الوصف والتأثير البرمجي
manage_options Administrator الصلاحية الأشهر للمدراء! تُستخدم للوصول لإعدادات الموقع العامة وحفظ خيارات الإضافات.
install_plugins Administrator تثبيت إضافات جديدة إلى الموقع.
activate_plugins Administrator تفعيل أو تعطيل الإضافات المثبتة.
edit_plugins Administrator تعديل أكواد الإضافات مباشرة من محرر ووردبريس المدمج.
delete_plugins Administrator حذف ملفات الإضافات نهائياً من السيرفر.
install_themes Administrator تثبيت قوالب جديدة للموقع.
switch_themes Administrator تغيير القالب المفعّل حالياً للموقع.
edit_themes Administrator تعديل ملفات القالب من محرر التنسيقات الإداري.
edit_theme_options Administrator التعديل على خيارات القالب والودجات (Widgets) والمخصص (Customizer) والقوائم.
update_core Administrator / Super Admin تحديث نظام ووردبريس الأساسي لإصدارات جديدة.

2. إدارة المستخدمين والأعضاء (User Management Capabilities)

تُستخدم للتحكم في حسابات وتراخيص وأدوار المستخدمين داخل النظام:

الصلاحية (Capability) الوصف والتأثير البرمجي
list_users رؤية وعرض قائمة جميع المستخدمين والأعضاء في لوحة التحكم.
create_users إنشاء وإضافة حسابات مستخدمين جدد يدوياً.
edit_users تعديل بيانات وملفات المستخدمين الآخرين وكلمات مرورهم.
delete_users حذف حسابات المستخدمين وتنظيف/نقل منشوراتهم.
promote_users تغيير دور المستخدم (مثلاً ترقيته من كاتب Contributor إلى محرر Editor).
remove_users إزالة مستخدم من موقع محدد داخل شبكات المالتوسايت (Multisite Network).

3. إدارة المقالات والأنواع المخصصة (Posts & Custom Post Types)

تضمن التحكم في إنشاء وتعديل ونشر المقالات (يمتلك أغلبها المحرر Editor والكاتب Author):

الصلاحية (Capability) فئة الصلاحية الوصف والتأثير البرمجي
read أساسية (Basic) صلاحية أساسية تسمح للمستخدم بالدخول للوحة التحكم وقراءة المقالات المتاحة له (حتى للـ Subscriber).
edit_posts أساسية (Basic) إنشاء وتعديل المقالات الخاصة بحساب المستخدم نفسه.
publish_posts أساسية (Basic) نشر المقالات مباشرة لتصبح مرئية للزوار في الموقع.
delete_posts أساسية (Basic) حذف المسودات والمقالات الخاصة بالحساب نفسه.
edit_others_posts متقدمة للمحررين (Editor) تعديل مقالات كتبها مستخدمون وكُتّاب آخرون.
delete_others_posts متقدمة للمحررين (Editor) حذف مقالات كتبها مستخدمون آخرون.
edit_published_posts متقدمة للمحررين (Editor) تعديل المقالات بعد أن تم نشرها بالفعل على الموقع.
delete_published_posts متقدمة للمحررين (Editor) حذف المقالات المنشورة بالفعل.
read_private_posts متقدمة للمحررين (Editor) قراءة المقالات المحمية والمغلقة كخاصة (Private).
edit_private_posts متقدمة للمحررين (Editor) تعديل المقالات الخاصة.
delete_private_posts متقدمة للمحررين (Editor) حذف المقالات الخاصة.

4. إدارة الصفحات الثابتة (Pages Capabilities)

الصفحات الثابتة (Pages) تمتاز بصلاحيات منفصلة عن المقالات التقليدية (Posts):

الصلاحية (Capability) الوصف والتأثير البرمجي
edit_pages إنشاء وتعديل الصفحات الثابتة الخاصة بالحساب.
publish_pages نشر الصفحات الثابتة لتصبح مرئية في الواجهة.
delete_pages حذف الصفحات الثابتة الخاصة بالحساب.
edit_others_pages تعديل صفحات أنشأها كُتّاب أو مستخدمون آخرون.
delete_others_pages حذف صفحات أنشأها مستخدمون آخرون.
edit_published_pages تعديل الصفحات الثابتة المنشورة بالفعل.
delete_published_pages حذف الصفحات الثابتة المنشورة بالفعل.

5. الوسائط والملفات والتعليقات والتصنيفات (Media, Comments & Taxonomies)

القسم الصلاحية (Capability) الوصف والتأثير البرمجي
الوسائط والملفات upload_files رفع الصور والملفات والمستندات إلى مكتبة الوسائط.
الوسائط والملفات unfiltered_html إدخال أكواد HTML وJavaScript كاملة دون تصفيتها بواسطة ووردبريس (صلاحية حساسة جداً للمدراء والمحررين).
التعليقات moderate_comments الموافقة على تعليقات الزوار، تعديلها، أو حظرها وسحبها للسلة.
التصنيفات والوسوم manage_categories إضافة، تعديل، وحذف التصنيفات (Categories) والوسوم (Tags) والتاكسونومي المخصص.
💡 ملاحظات واحترافيات مخصصة للمطورين (Pro Tips for Developers):
  1. التحقق من كائن أو عنصر محدد (Object Check):
    يمكنك تمرير الـ ID الخاص بمقال أو عنصر معين في البرامتر الثاني للتحقق مما إذا كان المستخدم يملك صلاحية تعديل هذا المقال بالذات:
    if ( current_user_can( 'edit_post', $post_id ) ) { ... }
  2. إنشاء صلاحيات خاصة بإضافتك (Custom Capabilities):
    عند إنشاء إضافة مخصصة، يمكنك ابتكار صلاحية جديدة باسم إضافتك ومنحها لأدوار محددة للتحكم في الوصول:
    if ( current_user_can( 'manage_kidscare_clinic' ) ) { ... }

3. التحكم في الواجهة الأمامية (Frontend Conditions)

تُستخدم هذه الشروط لتحديد نوع الصفحة التي يزورها الزائر حالياً في الواجهة الأمامية:

  • is_front_page() / is_home(): is_front_page() تتحقق ممّا إذا كان الزائر واقفاً على الصفحة الرئيسية للموقع (سواء كانت صفحة ثابتة أو آخر المقالات). تُستخدم لتحميل السلايدر (Slider) أو الأكواد الخاصة بالصفحة الرئيسية فقط دون باقي الصفحات.
  • is_single() / is_page() / is_singular():
    • is_single(): للتحقق من أن الصفحة الحالية هي مقال فردي (Post) أو Post Type مخصص.
    • is_page(): للتحقق من أن الصفحة الحالية هي صفحة ثابتة (Page) (مثل صفحة "من نحن").
    • is_singular('book'): تشمل الاثنين معاً + أي نوع منشور مخصص (Custom Post Type).
  • is_category() / is_tag() / is_tax(): للتحقق من عرض صفحات التصنيفات والوسوم والوسوم التخصصية (Taxonomies).
  • is_archive() / is_search() / is_404(): للتحقق من صفحة الأرشيف العام، صفحة نتائج البحث، أو صفحة الخطأ 404.
frontend-singular-example.php
<?php
// هل الزائر في صفحة عرض منشور من نوع "book"؟
if ( is_singular( 'book' ) ) {
    echo "أنت تقرأ كتاباً الآن!";
}

// هل الزائر في الصفحة الرئيسية فقط؟
if ( is_front_page() ) {
    wp_enqueue_style( 'kcc-home-slider-css' );
}

📊 جدول ملخص شامل لأهم الدوال الشرطية في ووردبريس:

الشرط (Conditional Tag) المكان والسياق الذي يفحصه أكثر استخدام شائع له
is_admin() صفحات لوحة التحكم (wp-admin) تحميل سكربتات وكلاسات الإدارة فقط.
wp_doing_ajax() طلبات الخلفية السريعة (AJAX Requests) معالجة استجابات الـ AJAX دون طباعة HTML.
wp_doing_cron() المهام المجدولة (WP-Cron Jobs) تخفيف الحمل أثناء تشغيل الصيانة التلقائية.
wp_is_json_request() طلبات REST API والتطبيقات الخارجيّة تخصيص البيانات المرجعة في صيغة JSON.
current_user_can('cap') صلاحية المستخدم الحالي الحقيقية حماية الأكواد والروابط الحساسة وعمليات الحذف.
is_user_logged_in() حالة تصفح الزائر (تسجيل الدخول) إظهار وإخفاء محتوى للأعضاء والزوار.
is_front_page() الواجهة الأمامية (الصفحة الرئيسية) تخصيص تأثيرات وسلايدر الصفحة الرئيسية.
is_singular('custom_type') صفحة منشور منفرد لـ CPT معين إضافة عناصر وميتا بوكس لنوع منشور محدد.
is_ssl() اتصال بروتوكول HTTPS الآمن تحميل الموارد عبر اتصالات مشفرة فقط.
