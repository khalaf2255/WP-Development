تحديد مسارات الإضافة والمحتوى (Determining Directories)

لماذا نبتعد عن المسارات الصلبة؟ حل Symlinks مع __FILE__، والتفرقة بين Client URL و Server Path.

1. العلة التقنية لمنع المسارات الصلبة (Why Avoid Hardcoded Paths?)

يتيح ووردبريس للمستخدمين والشركات تغيير اسم ومكان مجلد wp-content لأسباب أمنية وتنظيمية. علاوة على ذلك، فإن الثابت السحري في PHP __FILE__ يترجم الـ Symlinks تلقائياً. لذلك، فإن استخدام مسارات صلبة يتسبب في انكسار الإضافة تماماً.

الدالة نوع المخرج القيمة المرجعة النموذجية الاستخدام الرئيسي
plugins_url('js/script.js', __FILE__) URL كامل للمتصفح https://site.com/wp-content/plugins/my-plugin/js/script.js تحميل السكريبتات بـ wp_enqueue_script
plugin_dir_url(__FILE__) URL مجلد الإضافة https://site.com/wp-content/plugins/my-plugin/ عنوان الويب المباشر لمجلد الإضافة
plugin_dir_path(__FILE__) Server Path للسيرفر /var/www/html/wp-content/plugins/my-plugin/ تضمين الملفات بـ require_once
plugin_basename(__FILE__) Relative Path نسبي my-plugin/my-plugin.php التعرف على الإضافة في الـ Hooks والشبكات

2. دوال مسارات ووردبريس الشاملة (WordPress Core Directory Functions)

بالإضافة لدوال الإضافات، يوفر ووردبريس دوال مسارات عامة للوصول لكافة أجزاء النظام:

  • home_url(): عنوان الصفحة الرئيسية للموقع Web Front-end.
  • site_url(): عنوان مجلد ووردبريس الأساسي الذي يحتوي على ملفات النواة.
  • admin_url(): عنوان لوحة التحكم /wp-admin/.
  • includes_url(): عنوان مجلد تضمين النواة /wp-includes/.
  • content_url(): عنوان مجلد المحتوى /wp-content/.
  • wp_upload_dir(): يعيد Array تفصيلي بمسارات وعناوين مجلد المرفقات والرفوعات.
