تحديد مسارات الإضافة والمحتوى (Determining Directories)

لماذا نبتعد عن المسارات الصلبة؟ حل Symlinks مع __FILE__، والتفرقة بين Client URL و Server Path.

1. العلة التقنية لمنع المسارات الصلبة (Why Avoid Hardcoded Paths?)

هذا الموضوع يُعتبر أحد أهم أركان البرمجة السليمة والمحترفة في ووردبريس، ومهم جداً لمنع توقف الموقع أو ظهور خطأ الصفحة البيضاء القاتل (White Screen of Death).

ما هي "المسارات الصلبة" (Hardcoded Paths) ولماذا نبتعد عنها؟

المسار الصلب هو كتابة عنوان الملف أو المجلد بشكل يدوي وثابت ومباشر في كود الـ PHP، مثل:

bad-hardcoded-path.php
<?php
// ❌ مسار صلب خافٍ ومضر جداً:
require_once '/var/www/html/wp-content/plugins/my-plugin/includes/admin.php';
💡 العلة التقنية لمنع المسارات الصلبة:
  1. تغير بيئة التشغيل (Environments): عندما تبرمج الإضافة على جهازك الشخصي (Localhost) سيكون المسار مثلاً C:/xampp/htdocs/... وعند نقلها لسيرفر استضافة حقيقي سيتغير المسار إلى /var/www/html/.... إذا كتبت مساراً صلباً، ستتوقف الإضافة عن العمل فوراً!
  2. تغيير مجلد wp-content لأسباب أمنية: كثير من أصحاب المواقع والشركات يقومون بتغيير اسم مجلد wp-content إلى اسم آخر (مثل assets أو app) لحماية الموقع من الثغرات، أو يغيرون مكانه خارج المجلد الرئيسي للموقع. كتابة المسار الصلب تؤدي لانكسار روابط الصور والملفات فوراً.
  3. مشكلة الـ Symlinks (الروابط الرمزية): عند تطوير الإضافات، يقوم بعض المطورين بعمل "اختصار" للمجلد (Symlink) من مكان آخر في السيرفر. الثابت السحري في PHP __FILE__ يقرأ المسار الحقيقي الفيزيائي على القرص الصلب (Physical Path) وليس المسار الظاهري، مما يُسبب تعارضاً إذا لم تُستخدم دوال ووردبريس المخصصة لمعالجته.

2. التفرقة الأساسية: الفرق بين Server Path و Client URL

قبل استخدام الدوال، يجب أن تفرق بين مفهومين حاسمين في معمارية مواقع الويب وووردبريس:

Server Path vs Client URL Architecture
                  ┌─────────────────────────────────────────┐
                  │              موقع ووردبريس              │
                  └────────────────────┬────────────────────┘
                                       │
                ┌──────────────────────┴──────────────────────┐
                ▼                                             ▼
       [ Server Path ]                                 [ Client URL ]
     مسار داخل السيرفر                                 عنوان في المتصفح
---------------------------------             ---------------------------------
• يقرأه المعالج PHP فقط.                     • يقرأه المتصفح (Browser) والزائر.
• يُستخدم مع:                                 • يُستخدم مع:
  require_once, include, file_exists            wp_enqueue_script, <img>, <link>
• مثال:                                       • مثال:
  /var/www/html/wp-content/...                  https://site.com/wp-content/...

3. شرح الدوال وأهميتها وتفاصيل معاملات كل دالة (Parameters Breakdown)

ليعفيك ووردبريس من دوامة المسارات، وفر لك هذه الدوال الجاهزة التي تحسب المسار الصحيح ديناميكياً مهما تغير مكان الموقع أو بيئة الاستضافة:

1️⃣ plugin_dir_path( $file ) ➔ [ Server Path ]

  • ماذا ترجع؟ المسار البرمجي الداخلي للأنظمة والسيرفر، وتنتهي دائماً بـ slash /.
  • متى نستخدمها؟ لتضمين ملفات PHP داخل بعضها البعض باستعمال require_once أو include.
  • عدد المعاملات (Parameters Count): معامل واحد فقط (1 Parameter).
  • تعريف المعامل:
    • $file (نوع البيانات: string - إجباري): مسار الملف الحالي على السيرفر، وعادة ما نمرر الثابت السحري __FILE__.
plugin_dir_path_example.php
<?php
// تضمين ملف داخل الإضافة بشكل آمن وديناميكي
require_once plugin_dir_path( __FILE__ ) . 'includes/functions.php';

2️⃣ plugin_dir_url( $file ) ➔ [ Client URL ]

  • ماذا ترجع؟ رابط الـ HTTP المباشر للمجلد الخاص بإضافتك، وتنتهي دائماً بـ slash /.
  • متى نستخدمها؟ عندما تريد طباعة رابط صورة أو إحالة لمجلد إضافتك في الواجهة.
  • عدد المعاملات (Parameters Count): معامل واحد فقط (1 Parameter).
  • تعريف المعامل:
    • $file (نوع البيانات: string - إجباري): مسار الملف الحالي على السيرفر، وعادة ما نمرر الثابت السحري __FILE__.
plugin_dir_url_example.php
<?php
// طباعة رابط صورة مباشرة في HTML الواجهة
echo '<img src="' . plugin_dir_url( __FILE__ ) . 'images/logo.png" alt="Logo" />';

3️⃣ plugins_url( $path, $plugin ) ➔ [ Client URL ]

  • ماذا ترجع؟ الرابط الكامل لملف معين (JS أو CSS أو صورة) داخل إضافتك.
  • متى نستخدمها؟ بشكل أساسي عند تسجيل وتضمين ملفات السكربتات والتنسيقات لـ ووردبريس بـ wp_enqueue_script.
  • عدد المعاملات (Parameters Count): معاملان اثنان (2 Parameters - كلاهما اختياري في الأصل ولكن يُمرران عملياً).
  • تعريف المعاملات:
    • $path (نوع البيانات: string - اختياري، الافتراضي ''): المسار النسبي للملف المراد جلب رابطه (مثل 'js/script.js').
    • $plugin (نوع البيانات: string - اختياري، الافتراضي ''): المسار المباشر لملف الإضافة على السيرفر (وعادة ما نمرر __FILE__) لحساب الرابط بالنسبة لمجلد إضافتك.
plugins_url_example.php
<?php
// تسجيل وتضمين ملف Javascript بشكل آمن
wp_enqueue_script( 
    'my-script', 
    plugins_url( 'assets/js/main.js', __FILE__ ) 
);

4️⃣ plugin_basename( $file ) ➔ [ Relative Path ]

  • ماذا ترجع؟ مسار نسبي مختصر يربط بين مجلد الإضافات الرئيسي والملف الحالي (مثل: my-plugin/my-plugin.php).
  • متى نستخدمها؟ للتعرف على الإضافة في الخطافات (Hooks) الخاصة بالنظام، مثل فلتر plugin_action_links_ لإضافة رابط الإعدادات.
  • عدد المعاملات (Parameters Count): معامل واحد فقط (1 Parameter).
  • تعريف المعامل:
    • $file (نوع البيانات: string - إجباري): المسار المطلق الكامل للملف على السيرفر (عادة __FILE__) ليقوم ووردبريس باقتطاعه وإرجاع المسار النسبي فقط ابتداءً من مجلد plugins/.
plugin_basename_example.php
<?php
// ربط فلتر خيارات الإضافة بصفحة Plugins في لوحة التحكم
add_filter( 'plugin_action_links_' . plugin_basename( __FILE__ ), 'my_settings_link' );
الدالة والتعريض البرمجي عدد المعاملات شرح المعاملات (Parameters) نوع المخرج والمرجع الاستخدام الرئيسي
plugin_dir_path( $file ) 1 $file: مسار الملف الحالي (__FILE__) Server Path للسيرفر تضمين الملفات بـ require_once أو include
plugin_dir_url( $file ) 1 $file: مسار الملف الحالي (__FILE__) URL مجلد الإضافة المباشر عنوان الويب المباشر لمجلد الإضافة للصور والروابط
plugins_url( $path, $plugin ) 2 1. $path: المسار النسبي للملف
2. $plugin: مسار الإضافة (__FILE__) 		URL كامل للمتصفح تحميل السكريبتات والتنسيقات بـ wp_enqueue_script
plugin_basename( $file ) 1 $file: المسار المطلق للملف (__FILE__) Relative Path نسبي للمجلد التعرف على الإضافة في الـ Hooks والفلترة

مثال تطبيقي عملي: استدعاء وتضمين ملف JavaScript عبر plugins_url()

في تطوير ووردبريس الاحترافي، لا نكتفي بإنشاء مسار الملف بل نربطه بالـ Action Hook الرسمي wp_enqueue_scripts بالشكل التالي:

enqueue-script-example.php
<?php
add_action( 'wp_enqueue_scripts', function () {
    wp_enqueue_script(
        'my-custom-js',                             // 1. اسم مميز للسكربت (Handle)
        plugins_url( 'js/script.js', __FILE__ ),     // 2. مسار الملف الصحيح عبر plugins_url
        array(),                                    // 3. التبعيات (مثل array('jquery') إن وجد)
        '1.0.0',                                    // 4. رقم الإصدار
        true                                        // 5. true ليركب في الفوتر قبل إغلاق </body>
    );
} );
🎯 ملخص ذهبي سريع:
  • تضمين ملفات PHP البرمجية؟ ➔ استخدم plugin_dir_path()
  • ربط ملفات CSS / JS / Images؟ ➔ استخدم plugins_url() أو plugin_dir_url()
  • استهداف الإضافة في الـ Hooks والفلترة؟ ➔ استخدم plugin_basename()

2. دوال مسارات ووردبريس الشاملة (WordPress Core Directory Functions)

هذه الدوال هي أدوات الملاحة والتوجيه الأساسية في ووردبريس، وتُستخدم لجلب العناوين والمسارات المختلفة للموقع بشكل ديناميكي دون كتابة أجزاء من الرابط يدوياً (مثل https://example.com/wp-content).

1. التفرقة المهمة: home_url() مقابل site_url()

كثير من المطورين يخلطون بين هاتين الدالتين، ولكن بينهما فرق جوهري وتنفيذي حاسم في معمارية الموقع:

  • أ. home_url( $path ) ➔ عنوان الواجهة الأمامية للموقع (Web Front-end URL):
    • ماذا ترجع؟ الرابط الرئيسي الذي يزوره المستخدمون لتصفح الموقع (مثلاً: https://mysite.com).
    • متى نستخدمها؟ عندما تريد توجيه الزائر لصفحة داخل الموقع، أو إنشاء روابط داخلية في القوائم والأزرار.
home_url_example.php
<?php
// إرجاع رابط صفحة اتصل بنا بشكل ديناميكي
$contact_url = home_url( '/contact-us/' ); 
// النتيجة: https://mysite.com/contact-us/
  • ب. site_url( $path ) ➔ عنوان مجلد ووردبريس الأساسي (WordPress Core Directory):
    • ماذا ترجع؟ المكان الحقيقي الذي تعيش فيه ملفات نواة ووردبريس (WordPress Core Files).
    • متى يختلف عن home_url()؟ في بعض المواقع الاحترافية، يقوم المطور بوضع ملفات ووردبريس في مجلد فرعي (مثل https://mysite.com/wordpress) ولكن الموقع يفتح للزوار عبر https://mysite.com.
      - home_url() ستُرجع: https://mysite.com
      - site_url() ستُرجع: https://mysite.com/wordpress
    • متى نستخدمها؟ للوصول إلى ملفات النظام نفسها مثل صفحة تسجيل الدخول (wp-login.php).
site_url_example.php
<?php
// إرجاع رابط صفحة تسجيل الدخول بالنواة
$login_url = site_url( 'wp-login.php' );
// النتيجة: https://mysite.com/wp-login.php

2. دوال الوصول للوحة التحكم والنواة

أ. admin_url( $path ) ➔ عنوان لوحة التحكم (wp-admin)

  • ماذا ترجع؟ رابط مجلد الإدارة wp-admin مُضافاً إليه المسار الذي تطلبه.
  • متى نستخدمها؟ لتوجيه المدير لصفحة إعدادات إضافتك، أو لرابط صفحة معينة في لوحة التحكم (مثل صفحة إضافة مقال جديد).
admin_url_example.php
<?php
// رابط صفحة إعدادات إضافتك في لوحة التحكم
$settings_url = admin_url( 'admin.php?page=my-plugin-settings' );
// النتيجة: https://mysite.com/wp-admin/admin.php?page=my-plugin-settings

ب. includes_url( $path ) ➔ عنوان مجلد wp-includes

  • ماذا ترجع؟ رابط المجلد الذي يحتوي على مكتبات السكربتات والأكواد الأساسية لووردبريس (مثل jQuery و MediaElement).
  • متى نستخدمها؟ نادراً ما تحتاج إليها، ولكنها تُستخدم إذا أردت استدعاء أصول (Assets) أو سكربتات مدمجة مسبقاً في نواة النظام.
includes_url_example.php
<?php
// رابط مكتبة jQuery المدمجة بالنواة
$jquery_url = includes_url( 'js/jquery/jquery.min.js' );

3. دوال الوصول للمحتوى والملفات المرفوعة

أ. content_url( $path ) ➔ عنوان مجلد المحتوى (wp-content)

  • ماذا ترجع؟ الرابط المباشر لمجلد wp-content (والذي يحتوي على القوالب والإضافات والملفات المرفوعة).
  • متى نستخدمها؟ للوصول لأي ملفات عامة مخزنة داخل مجلد wp-content.
content_url_example.php
<?php
// رابط ملف تنسيقات عام في مجلد wp-content
$custom_css = content_url( 'uploads/custom-styles.css' );

ب. wp_upload_dir() ➔ الدالة المظلية للرفوعات (Uploads Array)

  • ما المُميز فيها؟ هذه الدالة لا ترجع مجرد نص عادي (String)، بل ترجع مصفوفة تفصيلية (Array) تحتوي على المسارات للسيرفر (Paths) والعناوين للمتصفح (URLs) لمجلد المرفقات الحقيقي (بما في ذلك تقسيمات السنة والشهر تلقائياً).
  • متى نستخدمها؟ عندما تريد رفع ملف برمجياً إلى السيرفر، أو قراءة ملف تم رفعه في مجلد uploads.
wp_upload_dir_structure.php
<?php
$upload_dir = wp_upload_dir();

/* 
المخرجات تكون مصفوفة تفصيلية بالشكل التالي:
Array (
    [path]    => /var/www/html/wp-content/uploads/2026/08   (مسار السيرفر للشهر الحالي)
    [url]     => https://site.com/wp-content/uploads/2026/08 (رابط المتصفح للشهر الحالي)
    [subdir]  => /2026/08                                   (المجلد الفرعي)
    [basedir] => /var/www/html/wp-content/uploads          (مسار السيرفر الأساسي للرفوعات)
    [baseurl] => https://site.com/wp-content/uploads        (رابط المتصفح الأساسي للرفوعات)
    [error]   => false                                      (حالة وجود أخطاء في الصلاحيات)
)
*/

🛠️ مثال عملي لاستخدام مصفوفة wp_upload_dir():

wp_upload_dir_usage.php
<?php
$upload_dir = wp_upload_dir();

// 1. استخدام [basedir] لإنشاء وحفظ ملف جديد على السيرفر بـ PHP
$file_path = $upload_dir['basedir'] . '/my-custom-folder/data.json';
file_put_contents( $file_path, json_encode( $data ) );

// 2. استخدام [baseurl] لعرض رابط الملف للزائر في المتصفح
$file_url = $upload_dir['baseurl'] . '/my-custom-folder/data.json';
echo '<a href="' . esc_url( $file_url ) . '">تحميل الملف</a>';
🎯 ملخص سريع للاستخدام اليومي لدوال النواة:
  • توجيه الزائر لصفحة داخل الموقع؟ ➔ home_url()
  • توجيه المستخدم لرابط في لوحة التحكم؟ ➔ admin_url()
  • توجيه المستخدم لصفحة تسجيل الدخول للنواة؟ ➔ site_url('wp-login.php')
  • رفع ملفات أو التعامل مع صور مرفوعة في السيرفر؟ ➔ wp_upload_dir()
