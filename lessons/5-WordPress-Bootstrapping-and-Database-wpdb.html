الدرس الخامس: تسلسل دورة الإقلاع والتعامل مع قاعدة البيانات ($wpdb)

🎥 أدوات ودليل صانع المحتوى لتسجيل هذا الدرس على يوتيوب

🎯 خطة الخطاب وافتتاحية الفيديو (Hook):

"إزاي بتتعامل مع قاعدة بيانات ووردبريس بأمان وبسرعة وتعمل استعلامات معقدة من غير ما تسبب ثقل للموقع أو تفتح ثغرات SQL Injection؟ في الفيديو ده هتشوف الكائن السحري $wpdb!"

🗣️ نقاط الشرح أثناء التسجيل:

  1. شرح دورة الإقلاع وقراءة ملفات wp-settings.php بسرعة.
  2. استدعاء global $wpdb; وكتابة استعلام آمن عبر $wpdb->prepare().
  3. التنبه للبادئة الديناميكية $wpdb->prefix وطباعة النتائج على الشاشة.

📘 التلخيص المترابط للموضوعات

٥.١ التسلسل البرمجي التفصيلي الكامل لدورة إقلاع ووردبريس (Bootstrapping Process)

عند طلب أي صفحة في ووردبريس، يمر النظام بتسلسل إقلاع ملفي وتنفيذي منتظم لشحن البيئة البرمجية الكاملة من نقطة استقبال الطلب وحتى عرض استجابة الـ HTML على متصفح الزائر. يغطي هذا التسلسل كافة المراحل والملفات والأحداث (Hooks) بالتفصيل التام دون اختصار:

HTTP Request ➔ index.php
  └── wp-blog-header.php
      ├── wp-load.php ➔ wp-config.php (ABSPATH & DB Credentials)
      │   └── wp-settings.php (Master Initialization Core)
      │       ├── mu-plugins & muplugins_loaded
      │       ├── Active Plugins & plugins_loaded
      │       ├── Pluggable & Theme Setup (setup_theme, functions.php, after_setup_theme)
      │       ├── Global Objects ($wpdb, $wp_rewrite, $wp, $wp_query, User Auth)
      │       └── Init & Loaded (init & wp_loaded)
      ├── wp() (URL Parsing & Main DB Query)
      └── template-loader.php (Template Hierarchy & Output Response)

المراحل والمحاور التفصيلية لدورة الإقلاع (من بداية الطلب إلى المخرجات):

١. مرحلة البداية والتوجيه (Initial Entry Points)

  • index.php ➔ يستدعي wp-blog-header.php: نقطة الاستقبال الأولى لجميع طلبات الموقع القادمة عبر الخادم.
  • wp-load.php ➔ يستدعي wp-config.php: يبحث عن ملف التهيئات لاستدعائه، حيث يُعرّف الثابت الأمني ABSPATH وثوابت قواعيد البيانات ومفاهيم التشفير.
  • wp-settings.php: الملف الرئيسي المسئول في خطوته الخامسة عن مسح مجلد الإضافات wp-content/plugins/ وقراءة ترويسات الإضافات المفعلة فقط وتحميلها في الذاكرة لتكون جاهزة للاستجابة للأحداث.

٢. تحميل الإضافات والأحداث المبكرة (Plugins & Early Hooks)

تتم بالكامل داخل ملف wp-settings.php:

  • تحميل الـ Drop-ins و Must-Use Plugins: تحميل إضافات الاستخدام الإجباري الواقعة في مجلد (wp-content/mu-plugins/)، ثم إطلاق الأكشن muplugins_loaded.
  • تحميل الإضافات المفعلة (Active Plugins): المسح التحليلي لروائس الإضافات المفعلة وتحميل ملفاتها الرئيسية، ثم إطلاق الأكشن المحوري plugins_loaded (المكان القياسي والبيئة الرسمية لبدء عمل وتنفيذ الإضافات).

٣. تهيئة القالب والبيئة الرئيسية (Theme & Core Setup)

  • تحميل وظائف النواة وقواعد الأمان: تحميل ملفات النواة المسؤولة عن الصلاحيات (capabilities.php)، إدارة المستخدمين، والتنقيح والفلترة (formatting.php)، بالإضافة لتضمين ملف pluggable.php (الذي يحتوي على الدوال القابلة للاستبدال وإعادة التعريف من الإضافات).
  • تهيئة القالب (Theme Initialization):
    • إطلاق الأكشن setup_theme.
    • تحميل ملف functions.php الخاص بالقالب المفعل (والقالب الأب في حال استخدام Child Theme).
    • إطلاق الأكشن after_setup_theme (تنسيق وتجهيز ميزات القالب مثل add_theme_support).
  • توثيق المستخدم والمُتغيرات العامة:
    • بناء وتأسيس الكائنات العامة الكبرى في الذاكرة: $wpdb (كائن قاعدة البيانات)، $wp_rewrite (نظام الروابط الدائمة)، $wp (كائن النظام الرئيسي)، و $wp_query (كائن الاستعلام).
    • تحديد هوية المستخدم الحالي والتحقق من الجلسة والصلاحيات (Authentication Check).

٤. تهيئة النظام واكتمال التحميل (Init & Loaded)

  • إطلاق الأكشن init: النقطة الرئيسية والمعيارية لتعريف أنواع المنشورات المخصصة (CPTs)، التصنيفات المخصصة (Taxonomies)، ونقاط النهاية للمكفولين (Endpoints).
  • إطلاق الأكشن wp_loaded: يعني نهاية تنفيذ ملف wp-settings.php بالكامل، واستكمال بناء وتجهيز بيئة ووردبريس في الذاكرة تماماً.

٥. استعلام البيانات وبناء الطلب (Query & Routing)

العودة لملف wp-blog-header.php لتنفيذ الخطوات التالية:

  • استدعاء الدالة wp(): تُنفّذ الدالة $wp->main() لفك تشفير الرابط المطلوب (URL Parsing & Routing).
  • تجهيز الاستعلام الرئيسي ($wp_query): تنفيذ الاستعلام في قاعدة البيانات لاستخراج المنشورات أو الصفحات المطلوبة بناءً على الرابط، وتحديد معالم حالة الصفحة (مثال: is_single(), is_page(), is_archive(), is_404()).

٦. شجرة القوالب وعرض المحتوى (Template Hierarchy & Output)

  • استدعاء template-loader.php: يُستدعى بواسطة wp-blog-header.php لاستخدام التسلسل الهرمي للقوالب (Template Hierarchy).
  • تحديد وتنفيذ ملف القالب (Template Matching): فحص شجرة الملفات داخل القالب لاختيار الملف المناسب للصفحة المطلوبة (مثل single.php, archive.php, 404.php وصولاً إلى index.php كخيار أخير).
  • إخراج الـ HTML النهائي: تنفيذ ملف القالب ودمج وسم الرأس wp_head() وتوسيم التذييل wp_footer() لإخراج استجابة الـ HTML الكاملة إلى متصفح الزائر.
💡 خلاصة ربط دورة الإقلاع للمذاكرة والامتحانات:

تبدأ الإضافة عملها الفعلي عند plugins_loaded، ثم يتم تحميل القالب عند setup_theme و after_setup_theme، ثم تُسجل السجلات والتصنيفات عند init، وبعد اكتمال wp_loaded تنفذ النواة الاستعلام عبر wp() ويتم اختيار ملف العرض عبر template-loader.php.

٥.٢ التعامل مع الكائن العام ($wpdb)

يوفر ووردبريس كائناً عاماً مجهزاً يُدعى $wpdb لإجراء الاستعلامات المباشرة على قاعدة البيانات بأمان وكفاءة عالية دون الحاجة لفتح الاتصال بـ MySQL يدوياً.

💡 استخدام البادئة الديناميكية $wpdb->prefix:

يجب دائماً استخدام $wpdb->prefix . 'table_name' بدلاً من التسمية الصلبة wp_users، لأن المستخدم قد يغير بادئة الجداول في ملف wp-config.php لأسباب أمنية.

💻 كود الدرس البرمجي (VS Code Dark Theme)

استعلامات آمنة ومحمية من ثغرات SQL Injection باستخدام $wpdb->prepare():

📄 database-operations.php PHP
<?php /** * Plugin Name: Database Handler Plugin * Description: كود مخصص لإجراء استعلامات آمنة ومحمية عبر الكائن $wpdb. */ if ( ! defined( 'ABSPATH' ) ) { exit; } function academic_fetch_active_users() { // استدعاء الكائن العام $wpdb داخل نطاق الدالة global $wpdb; // تعيين اسم الجدول بالبادئة الديناميكية $table_name = $wpdb->prefix . 'users'; // تجهيز الاستعلام وتحصين المتغيرات لمنع SQL Injection $query = $wpdb->prepare( "SELECT ID, user_login, user_email FROM {$table_name} WHERE user_status = %d ORDER BY ID DESC LIMIT %d", 0, 5 ); // تنفيذ الاستعلام وجلب النتائج ككائنات $results = $wpdb->get_results( $query ); return $results; }

📊 شبكة ربط المفاهيم والمقارنات

الدالة في $wpdb الوظيفة والهدف البرمجي
$wpdb->get_results() جلب عدة صفوف من النتائج على شكل مصفوفة كائنات (Array of Objects).
$wpdb->get_row() جلب صف واحد فقط من النتائج.
$wpdb->prepare() دالة التجهيز والتأمين الإجبارية لمنع ثغرات SQL Injection عبر تحصين القيم.

❓ أسئلة المراجعة واختبار الذات

📌 س1 (اختيار من متعدد): ما المكون المسؤول عن مسح وقراءة الإضافات المفعلة أثناء الإقلاع؟
✅ الإجابة النموذجية: wp-settings.php.
📌 س2 (سؤال مقالي): ما هي الفائدة من استخدام $wpdb->prepare() عند كتابة استعلام SQL؟
✅ الإجابة النموذجية: لتأمين الاستعلام وتطهير المتغيرات لمنع ثغرات حقن الاستعلامات (SQL Injection).

⚡ قائمة الحفظ السريع ليلة الامتحان

  • ملف wp-settings.php هو المسئول عن تحميل الإضافات المفعلة أثناء الإقلاع.
  • استخدم دائماً global $wpdb; لجلب كائن قاعدة البيانات داخل الدوال.
  • استخدم $wpdb->prefix لضمان التوافق مع بادئة الجداول المتغيرة.
  • الدالة $wpdb->prepare() إجبارية لحماية الاستعلامات من SQL Injection.
