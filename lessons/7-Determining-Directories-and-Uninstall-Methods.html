تحديد المسارات والعناوين الديناميكية وطرق التنظيف النهائي عند الحذف

شرح تفصيلي لدوال المسارات، التثبيت القانوني GPL، والفرق بين Deactivation و uninstall.php مع الأمان المعماري.

1. تحديد المسارات والعناوين الديناميكية (Determining Directories & URLs)

عند بناء إضافة ووردبريس، تحتاج بشكل دائم للإشارة إلى ملفات داخل مجلد الإضافة (مثل CSS و JavaScript أو ملفات PHP الفرعية). القاعدة الذهبية هي: لا تقم أبداً بكتابة مسارات صلبة (Hardcoded Paths) متضمنة كلمة wp-content!

⚠️ علة عدم استخدام المسارات الصلبة (The Technical Rationale):
  1. حرية تخصيص المسارات: يتيح ووردبريس للمستخدمين والشركات إعادة تسمية مجلد wp-content أو نقله خارج جذر الموقع تماماً (مثل بيئات Bedrock & Sage).
  2. الوصلات الرمزية (Symlinks): الثابت السحري في PHP __FILE__ يقوم بحل الـ Symlinks تلقائياً، وبالتالي المسارات الصلبة تنكسر تماماً إذا كانت الإضافة مرتبطة عبر Symlink.

الفرق بين المسار السيرفري (Path) والعنوان للمتصفح (URL)

يجب التمييز بدقة بين نوعين من المسارات داخل الإضافة:

النوع الدالة القياسية القيمة المرجعة الاستخدام التقني
Client URL plugins_url( 'js/app.js', __FILE__ ) https://site.com/wp-content/plugins/my-plugin/js/app.js تضمين الـ CSS/JS عبر wp_enqueue_script
Directory URL plugin_dir_url( __FILE__ ) https://site.com/wp-content/plugins/my-plugin/ مسار URL المجلد الرئيسي للإضافة (ينتهي بـ slash)
Server Path plugin_dir_path( __FILE__ ) /var/www/html/wp-content/plugins/my-plugin/ تضمين ملفات PHP عبر require_once
Plugin Basename plugin_basename( __FILE__ ) my-plugin/my-plugin.php المسار النسبي المستخدم في الـ Hooks والفلترة

كود تطبيقي: التضمين الآمن للملفات والـ Assets

includes/class-assets-loader.php
<?php
if ( ! defined( 'ABSPATH' ) ) {
    exit; // حماية الوصول المباشر
}

// 1. تضمين ملف PHP سيرفري باستخدام Server Path
require_once plugin_dir_path( __FILE__ ) . 'includes/helpers.php';

// 2. تسجيل وتضمين السكريبتات باستخدام Client URL
add_action( 'wp_enqueue_scripts', 'my_plugin_enqueue_assets' );

function my_plugin_enqueue_assets() {
    $script_url = plugins_url( 'assets/js/main.js', __FILE__ );
    
    wp_enqueue_script( 
        'my-plugin-script', 
        $script_url, 
        array( 'jquery' ), 
        '1.0.0', 
        true 
    );
}

3. آليات التنظيف وإلغاء التثبيت (Uninstall Methods)

🚨 الفرق الحاسم بين Deactivation و Uninstall: العديد من المطورين يقعون في خطأ قاتل بمسح خيارات الإضافة أو الجداول في register_deactivation_hook. التجميد (Deactivation) قد يكون مؤقتاً لتصحيح خطأ أو ترقية الإضافة، وبالتالي يُمنع مسح بيانات المستخدم أو الجداول أثناء Deactivation!
الإجراء (Action) عند التعطيل (Deactivation Hook) عند الحذف النهائي (Uninstall Method)
تفريغ الكاش والـ Transients المؤقتة ✅ نعم (مسموح) ❌ لا داعي (سيتم إزالة الإضافة)
إعادة تنظيف قواعد الروابط (Flush Permalinks) ✅ نعم (واجب للمنع 404) ❌ غير مطلوب
حذف خيارات الإضافة من wp_options ❌ ممنوع قطعياً ✅ واجب لتنظيف قاعدة البيانات
إسقاط الجداول الخاصة بـ $wpdb ❌ ممنوع قطعياً ✅ واجب للتنظيف الكامل

الطريقة القياسية: ملف uninstall.php

إنشاء ملف باسم uninstall.php في الجذر الرئيسي للإضافة هو الخيار المفضل معمارياً (Best Practice). يقوم ووردبريس بتشغيله تلقائياً فقط عندما يقوم المستخدم بالضغط على رابط "Delete" في لوحة التحكم.

🔒 حماية الملف من الوصول المباشر عبر WP_UNINSTALL_PLUGIN: تماماً كما استخدمنا ABSPATH لمنع تنفيذ ملفات الإضافة مباشرة، يجب التأكد في بداية uninstall.php من وجود الثابت WP_UNINSTALL_PLUGIN لتجنب قيام المعتدين بتنفيذ عمليات الحذف مباشرة من المتصفح!
uninstall.php
<?php
// 1. فحص الحماية الأمني الحاسم: التأكد أن ووردبريس هو من استدعى الملف
if ( ! defined( 'WP_UNINSTALL_PLUGIN' ) ) {
    die;
}

// 2. حذف خيارات الإضافة المخزنة في wp_options
$option_name = 'my_plugin_settings';
delete_option( $option_name );
delete_site_option( $option_name ); // دعم الشبكات المتعددة Multisite

// 3. إسقاط الجداول المخصصة عبر $wpdb
global $wpdb;
$table_name = $wpdb->prefix . 'my_plugin_logs';
$wpdb->query( "DROP TABLE IF EXISTS {$table_name}" );
💡 ملخص الربط الأمني والإنشائي:
  • في ملفات الإضافة العادية نستخدم if ( ! defined( 'ABSPATH' ) ) exit; للحماية من Direct Access.
  • في ملف uninstall.php نستخدم if ( ! defined( 'WP_UNINSTALL_PLUGIN' ) ) die; للحماية من Direct Access الحاذف.
  • عند التعامل مع المسارات نستخدم الدوال الديناميكية لتجنب انكسار المسارات عند نقل الموقع أو استخدام Symlinks.
