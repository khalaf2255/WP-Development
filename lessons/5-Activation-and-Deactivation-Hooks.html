خطاطيف التفعيل والتعطيل (Activation & Deactivation Hooks)

كيف تشغل الإجراءات عند تفعيل أو تعطيل الإضافة، إظهار إشعارات التفعيل Flash Notices، وحل مشكلة 404 مع Permalinks.

1. خطاطيف التفعيل والتعطيل (Activation & Deactivation Hooks)

توفر خطاطيف التفعيل والتعطيل طرقاً لتنفيذ روتينات برمجية فور ضغط المستخدم على زري **تفعيل (Activate)** أو **تعطيل (Deactivate)** في لوحة التحكم.

  • عند التفعيل (Activation): يمكنك إنشاء جداول مخصصة في DB، وضع قيم إعدادات افتراضية، أو تحديث قواعد الروابط (Rewrite Rules).
  • عند التعطيل (Deactivation): يمكنك تنظيف الملفات المؤقتة، إزالة الـ Transients والـ Cache، وتفريغ قواعد الروابط.

2. طريقة التسجيل والكود القياسي (Registration Method)

includes/activation-deactivation.php
<?php
// 1. تسجيل دالة التفعيل
register_activation_hook( __FILE__, 'pluginprefix_activate' );

// 2. تسجيل دالة التعطيل
register_deactivation_hook( __FILE__, 'pluginprefix_deactivate' );
📌 المراجعة المعمارية للمسار المعطى: البرامتر الأول في كلتا الدالتين يشير إلى **المسار المطلق للملف الرئيسي للإضافة** (والذي يتضمن ترويسة Plugin Header). إذا قمت بكتابة هذه الدوال داخل ملف فرعي مستقلاً، يجب تمرير مسار الملف الرئيسي بدلاً من __FILE__.

3. تطبيق عملي حقيقي: حل مشكلة 404 مع Custom Post Type

أشهر تطبيق عملي لـ Activation Hook هو تحديث قواعد الروابط الدائمة (Permalinks) لتجنب أخطاء الصفحة غير موجودة 404 بعد تسجيل CPT جديد:

cpt-activation-example.php
<?php
/**
 * 1. تسجيل Custom Post Type عند الـ init
 */
function pluginprefix_setup_post_type() {
    register_post_type( 'book', array( 'public' => true ) );
}
add_action( 'init', 'pluginprefix_setup_post_type' );

/**
 * 2. دالة التفعيل: تسجيل الـ CPT وتحديث الـ Permalinks
 */
function pluginprefix_activate() {
    // تشغيل تسجيل الـ CPT حتى يتعرف عليه النظام في الذاكرة
    pluginprefix_setup_post_type();
    // تفريغ وتحديث قواعد الروابط فوراً لمنع 404
    flush_rewrite_rules();
}
register_activation_hook( __FILE__, 'pluginprefix_activate' );

/**
 * 3. دالة التعطيل: إزالة الـ CPT وتطهير الـ Permalinks
 */
function pluginprefix_deactivate() {
    unregister_post_type( 'book' );
    flush_rewrite_rules();
}
register_deactivation_hook( __FILE__, 'pluginprefix_deactivate' );
🚨 تحذير: التجميد ليس حذفا! لا تقم أبداً بمسح الخيارات المخزنة في wp_options أو إسقاط الجداول في دالة التعطيل register_deactivation_hook. التعطيل مجرد إيقاف مؤقت، أما مسح البيانات فيتم فقط في ملف uninstall.php.

4. عرض إشعار تفاعلي للمستخدم بعد التفعيل (Flash Notice Pattern)

عند تفعيل الإضافة، لا يمكن طباعة HTML مباشرة في دالة التفعيل لأن ووردبريس يقوم بعمل إعادة توجيه (Redirect) فورية. الحل الاحترافي هو استخدام نمط الخيار الخاطف (Flash Option Pattern):

activation-flash-notice.php
<?php
// 1. حفظ خيار مؤقت عند التفعيل وتسجيل سجل الأخطاء
register_activation_hook( __FILE__, function () {
    // تسجيل رسالة في ملف سجلات الأخطاء (wp-content/debug.log)
    error_log( 'تم تفعيل الإضافة بنجاح!' );

    // إضافة خيار مؤقت في قاعدة البيانات للتعرف على التفعيل
    add_option( 'my_plugin_just_activated', true );
} );

// 2. عرض إشعار للمستخدم في لوحة التحكم بعد التفعيل مباشرة ومسح الخيار المؤقت
add_action( 'admin_notices', function () {
    if ( get_option( 'my_plugin_just_activated' ) ) {
        delete_option( 'my_plugin_just_activated' );
        echo '<div class="notice notice-success is-dismissible"><p>تم تفعيل الإضافة بنجاح!</p></div>';
    }
} );

5. استخدام الأكشن admin_notices وطريقة الكتابة الصحيحة

الـ Action المسمى admin_notices هو خطاف حدث (Hook) مجاني ورسمي يوفر لك مكاناً محكّماً لطباعة رسائل التنبيه والإشعارات في أعلى صفحات لوحة تحكم ووردبريس (wp-admin).

💡 متى وأين يُستخدم؟

تستخدم هذا الخطاف عندما تريد إظهار رسالة للمدير (Admin) في سيناريوهات مثل:

  • نجاح العمليات: "تم حفظ الإعدادات بنجاح".
  • التنبيهات والتحذيرات: "تحذير: يجب عليك إدخال مفتاح الـ API لكي تعمل الإضافة".
  • الأخطاء والطلبات القاتلة: "خطأ: الإصدار الحالي من PHP غير مدعوم".

🛠️ كيف تكتبه بالصيغة القياسية الصحيحة؟

يوفر ووردبريس فئات CSS جاهزة لتنسيق شكل الإشعار، وتوضع الرسالة داخل عنصر <div class="notice ..."> بالطريقة التالية:

custom-admin-notice.php
<?php
/**
 * إضافة إشعار مخصص في أعلى لوحة التحكم
 */
add_action( 'admin_notices', 'my_custom_admin_notice' );

function my_custom_admin_notice() {
    ?>
    <div class="notice notice-success is-dismissible">
        <p>تم حفظ البيانات بنجاح!</p>
    </div>
    <?php
}

6. كلاسات الإشعارات المعتمدة في لوحة تحكم ووردبريس (WP Admin Notice Classes)

يوفر ووردبريس كلاسات CSS قياسية لتنسيق رسائل وإشعارات لوحة التحكم (admin_notices). يجب استخدام هذه الكلاسات لضمان التناسق البصري مع واجهة النظام:

اسم الكلاس (CSS Class) معاينة المظهر واللون الوصف والاستخدام التقني
notice كلاس أساسي الكلاس الرئيسي الواجب توفره في جميع عناصر إشعارات لوحة التحكم لتحديد المسافات والحدود.
notice-success أخضر 🟢 (Success) يُستخدم عند نجاح العمليات (مثل تفعيل إضافة، حفظ إعدادات، أو إرسال نموذج بنجاح).
notice-error أحمر 🔴 (Error) يُستخدم عند حدوث خطأ جسيم أو فشل عملية (مثل فشل الاتصال بالـ API أو عدم توفر متطلبات).
notice-warning برتقالي/أصفر 🟠 (Warning) يُستخدم للتحذيرات والتنبيهات الهامة التي تتطلب انتباه المستخدم دون أن تكون خطأً قاتلاً.
notice-info أزرق 🔵 (Info) يُستخدم لعرض معلومات وإرشادات عامة للمستخدم (مثل وجود تحديث اختياري أو تعليمات الاستخدام).
is-dismissible قابل للإغلاق ❌ يُضيف زر إغلاق تفاعلي (X) في الزاوية يسمح للمستخدم بإخفاء الإشعار من لوحة التحكم.
inline مضمن (Inline) يمنع الإشعار من العوم أعلى الصفحة ويجعله يظهر داخل حاوية أو نموذج محدد فقط.
