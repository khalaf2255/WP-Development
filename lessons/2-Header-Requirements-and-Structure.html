📘 الشرح التفصيلي لمتطلبات ترويسة الإضافة (Header Requirements)

يحتوي ملف PHP الرئيسي للإضافة في بدايته على تعليق توثيقي مخصص يُعرف بـ Plugin Header Comment. يخبر هذا التعليق نظام ووردبريس بأن الملف عبارة عن إضافة قابلة للتفعيل ويُزود النظام بالمعلومات اللازمة لعرضها في لوحة التحكم.

٢.١ الحقل الإجباري الأدنى (Minimum Fields)

في حده الأدنى المطلق، يجب أن يحتوي التعليق التوثيقي على حقل Plugin Name فقط ليتعرف ووردبريس عليه كإضافة قابلة للتفعيل:

/*
 * Plugin Name: YOUR PLUGIN NAME
 */

٢.٢ حقول الترويسة الـ 14 المتاحة (Header Fields)

يوفر ووردبريس 14 حقلاً رسمياً معتمداً لتوثيق الإضافة وتحديد متطلبات تشغيلها وأمانها التحديثي والاعتماديات:

اسم الحقل (Header Field) الوصف والتأثير البرمجي ملاحظات ودواعي الاستخدام
Plugin Name: اسم الإضافة (إجباري - Required). يُعرض في قائمة الإضافات في لوحة التحكم Admin. الحقل الوحيد الإجباري إطلاقاً.
Plugin URI: رابط الصفحة الرئيسية الخاصة بالإضافة (مثال: على موقعك الشخصي). ملاحظة: لا يُسمح بإدراج رابط WordPress.org هنا، بل رابطك المستقل.
Description: وصف مختصر للإضافة وما تقدمه من وظائف وميزات. يُفضل ألا يتجاوز الوصف 140 حرفاً ليكون ممتازاً في العرض.
Version: رقم الإصدار الحالي للإضافة (مثال: 1.0 أو 1.0.3). يُستخدم لمتابعة ومقارنة التحديثات.
Requires at least: أدنى إصدار مطلوب من نظام ووردبريس لعمل الإضافة. مثال: 5.2 أو 6.0.
Requires PHP: أدنى إصدار مطلوب من لغة البرمجة PHP. مثال: 7.4 أو 8.1 لحماية النظام من الأخطاء.
Author: اسم مبرمجة الإضافة أو فريق المطورين (يمكن فصل الأسماء بفواصل). يظهر بجوار الإضافة كحق حقوق المطور.
Author URI: رابط موقع المطور أو حسابه الرسمي على WordPress.org. رابط الملف الشخصي للمؤلف.
License: الاسم المختصر (Slug) لرخصة البرمجية (مثل GPLv2 أو GPL-2.0-or-later). يجب أن تتوافق الإضافة مع رخصة GNU General Public License.
License URI: رابط النص الكامل للرخصة (مثل https://www.gnu.org/licenses/gpl-2.0.html). توثيق الرخصة القانونية.
Text Domain: نطاق النصوص الخاص بالترجمة والتدويل (gettext domain). ضروري جداً لتوفير ترجمات الإضافة لعدة لغات (i18n).
Domain Path: مسار مجلد الترجمات داخل الإضافة (مثل /languages). يحدد لووردبريس مسار ملفات .mo و .po.
Network: تحديد ما إذا كانت الإضافة تُفعل على مستوى الشبكة بالكامل فقط (Multisite). تأخذ قيمة true فقط، وتُترك فارغة إذا لم تكن مطلوبة.
Update URI: رابط تحديث الإضافة الخاص لمنع استبدالها برمجياً عن طريق الخطأ بمحدثات من مستودع WordPress.org ذات الاسم المشابه. تمت إضافته رسمياً في ووردبريس 5.8 لحماية الإضافات الخاصة المخصصة.
Requires Plugins: اعتماديات الإضافات (ميزة WordPress 6.5 الجديدة). قائمة بأسماء الإضافات المطلوبة لتشغيل هذه الإضافة (فواصل بين slugs الإضافات). مثال: woocommerce, my-dependency-plugin. يحظر تثبيت الإضافة إلا بتوفر الاعتماديات!

٢.٣ ملاحظة هامة: مقارنة أرقام الإصدارات عبر version_compare()

⚠️ كيف يتعامل ووردبريس مع أرقام الإصدارات؟

يستخدم ووردبريس دالة PHP القياسية version_compare() للمقارنة بين أرقام إصدارات الإضافة القديمة والحديثة. لذلك قبل إطلاق إصدار جديد، يجب التأكد من أن الدالة تعتبر الرقم الجديد أصلح وأكبر من القديم.

مثال توضيحي: الرقم 1.02 يُعتبر برمجياً في PHP أكبر من الرقم 1.1 (لأن 2 أكبر من 1 بعد الفاصلة). فلذلك يجب مراعاة نمط الترقيم المعياري مثل Semantic Versioning (1.0.2 بدلاً من 1.02).

💻 كود الدرس البرمجي

١. كود الترويسة القياسي الشامل (مع اعتماديات WordPress 6.5 و Update URI):

📄 standard-plugin-header.php PHP
<?php /** * Plugin Name: My Basics Plugin * Plugin URI: https://example.com/plugins/the-basics/ * Description: إضافة شاملة تُطبق جميع حقول الترويسة المعيارية المعتمدة رسمياً. * Version: 1.10.3 * Requires at least: 5.2 * Requires PHP: 7.2 * Author: John Smith * Author URI: https://author.example.com/ * License: GPL v2 or later * License URI: https://www.gnu.org/licenses/gpl-2.0.html * Update URI: https://example.com/my-plugin/ * Text Domain: my-basics-plugin * Domain Path: /languages * Requires Plugins: woocommerce, my-custom-dependency */ // منع الوصول المباشر للملف لأسباب أمنية if ( ! defined( 'ABSPATH' ) ) { exit; } // بداية كود الإضافة function mbp_init_plugin() { // تشغيل وظائف الإضافة } add_action( 'plugins_loaded', 'mbp_init_plugin' );

٢. كود الترويسة المتقدم المدمج مع توثيق PHPDoc (@wordpress-plugin):

📄 advanced-phpdoc-header.php PHP
<?php /** * Main Plugin File * * @package PluginPackage * @author Your Name * @copyright 2026 Your Name or Company Name * @license GPL-2.0-or-later * * @wordpress-plugin * Plugin Name: Advanced PHPDoc Plugin * Plugin URI: https://example.com/plugin-name * Description: نموذج ترويسة مدمج يجمع بين توثيق PHPDoc للبرمجة وترووسية ووردبريس. * Version: 1.0.0 * Requires at least: 5.2 * Requires PHP: 7.2 * Author: Your Name * Author URI: https://example.com * Text Domain: plugin-slug * Domain Path: /languages * License: GPL v2 or later * License URI: http://www.gnu.org/licenses/gpl-2.0.txt * Update URI: https://example.com/my-plugin/ * Requires Plugins: my-plugin, yet-another-plugin */ if ( ! defined( 'ABSPATH' ) ) { exit; }

❓ أسئلة المراجعة واختبار الذات

📌 س1 (اختيار من متعدد): ما هو الحقل الإجباري الوحيد داخل تعليق ترويسة الإضافة (Plugin Header)؟
✅ الإجابة النموذجية: Plugin Name: هو الحقل الإجباري الوحيد إطلاقاً ليتعرف ووردبريس على الإضافة.
📌 س2 (اختيار من متعدد): ما هي الميزة الجديدة التي تم إدخالها في ووردبريس 6.5 لتحديد الإضافات المطلوبة لتشغيل إضافتك؟
✅ الإجابة النموذجية: حقل Requires Plugins: لتحديد قائمة بأسماء slugs الإضافات التي تعتمد عليها إضافتك.
📌 س3 (سؤال مقالي): كيف تقارن دالة version_compare() أرقام الإصدارات، وما الذي يجب تجنبه؟
✅ الإجابة النموذجية: تُستخدم دالة version_compare() في PHP لمقارنة أرقام الإصدارات. يجب تجنب الترقيم مثل 1.02 لأن الدالة تعتبر 1.02 أكبر من 1.1، ويجب استخدام الترقيم المعياري المكون من نقاط مثل 1.0.2.

⚡ قائمة الحفظ السريع ليلة الامتحان

  • Plugin Name: هو الحقل الإجباري الوحيد داخل ترويسة الإضافة.
  • الحقل Update URI: يمنع التحديثات العشوائية والاستبدال من مستودع WordPress.org.
  • الحقل Requires Plugins: (ووردبريس 6.5) يمنع تفعيل الإضافة إلا بتوفر الإضافات المعتمد عليها.
  • تستخدم ووردبريس دالة PHP version_compare() للمقارنة البرمجية بين الإصدارات.
  • يُفضل ألا يتجاوز الوصف في حقل Description: 140 حرفاً.
