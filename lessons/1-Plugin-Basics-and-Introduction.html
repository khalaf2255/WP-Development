مقدمة وخريطة طريق دليل تطوير الإضافات (Plugin Handbook)

تفكيك المعمارية الهيكلية للنظام، والقاعدة الذهبية في حماية النواة Core.

1. المعمارية الهيكلية لدليل الإضافات (Plugin Developer Handbook)

دليل تطوير الإضافات الرسمي هو المرجع الأساسي لتطوير برمجيات ووردبريس. بناءً على الخريطة الرسمية، لا تعمل الإضافة في ووردبريس كبرنامج منفصل، بل كـ توسعة ديناميكية (Dynamic Extension) ترتبط بالمنظومة عبر 4 ركائز معمارية رئيسية:

🔗 1. نظام الخطاطيف (Hooks System)
العصب المركزي المكون من Actions و Filters، ويتيح لك ضخ أكوادك أو تعديل البيانات أثناء تحميل الصفحة.
🗄️ 2. إدارة البيانات والكيانات (Entities)
التعامل مع قاعدة البيانات من خلال Custom Post Types, Taxonomies, Metadata, والحقول المخصصة.
🎨 3. الواجهة والتحكم (Admin UX)
دمج لوحات التحكم والإعدادات داخل الـ Dashboard عبر Administration Menus و Settings API.
⚙️ 4. الخلفية والمهام (Integrations & Cron)
الاتصال بالخدمات الخارجية عبر HTTP API، وتنفيذ المهمات المجدولة خلفياً عبر WP-Cron.

2. القاعدة الذهبية: حماية النواة (Don't Touch WordPress Core)

القاعدة الأولى والأهم في عالم ووردبريس هي: لا تقم أبداً بتعديل أي ملف من ملفات نواة ووردبريس (WordPress Core)!

📌 العلة التقنية (Technical Rationale): عند تحديث ووردبريس إلى إصدار جديد، يتم استبدال جميع ملفات النواة تلقائياً. أي تعديل مباشر في ملفات النواة سيتم مسحه فوراً، فضلاً عن التسبب في ثغرات أمنية وأخطاء برمجية غير متوقعة. البديل الآمن دائماً هو استخدام نظام الـ Hooks.

3. نمط الهيكل الأساسي للإضافة (Core Blueprint)

هذا كود مبسط يوضح كيف يتم تجميع مكونات الإضافة والتسجيل في نظام الـ Hooks دون المساس بالنواة:

my-first-plugin.php
<?php
/**
 * Plugin Name: Core Architecture Demo
 * Description: نموذج هيكلي موحد لتنفيذ إضافة ووردبريس قياسية.
 * Version: 1.0.0
 */

// 1. حماية الملف من الوصول المباشر
if ( ! defined( 'ABSPATH' ) ) {
    exit;
}

// 2. التسجيل في نظام الـ Hooks (إصدار Custom Post Type)
add_action( 'init', 'my_custom_post_type_init' );

function my_custom_post_type_init() {
    register_post_type( 'book', array(
        'public' => true,
        'label'  => 'Books',
    ) );
}
