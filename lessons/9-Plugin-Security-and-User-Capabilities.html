العقلية الأمنية وفحص صلاحيات المستخدمين (Security & Capabilities)

تأسيس العقلية الأمنية، قاعدة عدم الثقة بأي بيانات، وفحص صلاحيات الأدوار بـ current_user_can.

1. بناء العقلية الأمنية (Developing a Security Mindset)

هذا النص يُمثل **الفلسفة الأساسية والأصل الذهبي للأمان في ووردبريس (WordPress Security Core Philosophy)**. كثير من المطورين المبتدئين يقعون في فخ "طالما الكود يعمل بدون أخطاء، فكل شيء تمام"، بينما المطور المحترف يتعامل مع كل بيئة مدخلات كأنها محاولة اختراق محتملة!

🚨 فلسفة الأمان الذهبية: التعامل مع أي مدخل كتهديد محتمل!
نظراً لأن الإضافات والقوالب تعمل عبر ملايين المواقع بمختلف التهئيات السيرفرية، فإنها تمثل الهدف الأكثر استهدافاً من المخترقين. الكود الآمن لا يفترض البراءة في أي بيانات إطلاقاً.

تفكيك القواعد التوجيهية الأربع (The 4 Guiding Principles)

1. عدم الثقة مطلقاً (Never Trust Any Data)

الفكرة الأساسية: سواء كانت البيانات قادمة من حقل إدخال كتبه زائر ($_POST)، أو عبر رابط HTTP GET ($_GET)، أو كوكيز ($_COOKIE)، أو حتى استجابة قادمة من API خارجي موثوق، أو بيانات كانت مخزنة بالفعل في جدول wp_options.. لا تفترض أبداً أن البيانات سليمة 100%!

💡 لماذا البيانات المخزنة في قاعدة بياناتك قد تكون خطيرة؟
لأنه لو تم تجاوز فحص مدخل خبيث في مكان ما، أو وصلت البيانات لقاعدة البيانات عن طريق إضافة أخرى مثبتة على الموقع أو اختراق سابق، فإن طباعتك المباشرة لها دون تطهير ستتسبب في ثغرة XSS (Cross-Site Scripting) فوراً!

2. التحقق والرفض أفضل من مجرد التعقيم (Validation vs. Sanitization)

هنا يكمن الفرق الجوهري بين مطور يحمي موقعه بذكاء، ومطور يترك ثغرات خلفه:

  • أ. التحقق من الصحة (Validation) ➔ "هل البيانات بالطبيعة والشكل الصحيح؟"
    هو فحص البيانات قبل قبولها أو معالجتها، وإذا لم تكن تطابق الشرط تُرفض تماماً ويُعرض خطأ إيقافي بـ wp_die().
    مثال: إذا كنت تتوقع بريداً إلكترونياً، تحقق هل هو بريد بالفعل عبر is_email()؟ وإذا كان متوقعاً كـ رقم، هل هو رقم؟
validation-example.php
<?php
$email = $_POST['user_email'];

// Validation: إذا لم يكن البريد الإلكتروني صحيحاً، نوقف العملية فوراً!
if ( ! is_email( $email ) ) {
    wp_die( 'البريد الإلكتروني المدخل غير صحيح!' );
}
  • ب. التعقيم (Sanitization) ➔ "تنظيف البيانات وتجريدها من الأكواد الضارة"
    هو تنظيف المدخلات وتجريدها من أي أكواد JS أو HTML خطيرة قبل حفظها في قاعدة البيانات عبر دوال مثل sanitize_text_field().
sanitization-example.php
<?php
// Sanitization: تنظيف النص وتجريده من الوسوم الضارة قبل الحفظ
$clean_name = sanitize_text_field( $_POST['user_name'] );
update_option( 'kcc_admin_name', $clean_name );
💡 القاعدة الذهبية: Validate First (تحقق أولاً وارفض)، فإن مرت البيانات اعمل لها Sanitize (عقمها واحفظها).

3. التدرج الهرمي للصلاحيات (Capabilities & Nonces)

حتى لو كانت البيانات منظفة ومفحوصة، يظل السؤال الأهم: من الذي يقوم بهذا الإجراء؟ وهل قام به بنفسه؟

تأمين أي عملية حساسة ينقسم دائماً لجزأين مكملين لبعضهما:

  1. فحص الصلاحية (current_user_can): هل هذا الشخص مدير بالفعل لكي يحذف هذا المقال أو يغير الإعدادات؟
  2. فحص الشرعية والرمز الآمن (wp_verify_nonce): هل قام المستخدم بالنقر على الزر بنفسه داخل موقعنا؟ أم تم خداعه عبر رابط خبيث من موقع آخر لحثه على تنفيذ الأمر رغماً عنه (CSRF Attack)؟
capabilities-nonces-example.php
<?php
// 1. فحص الـ Nonce لمنع هجمات التزوير عبر المواقع (CSRF Attack)
if ( ! isset( $_POST['_wpnonce'] ) || ! wp_verify_nonce( $_POST['_wpnonce'], 'kcc_save_action' ) ) {
    wp_die( 'طلب غير مشروع أو رمز الـ Nonce غير صحيح!' );
}

// 2. فحص الصلاحية الفعلي للمستخدم الحقيقي
if ( ! current_user_can( 'manage_options' ) ) {
    wp_die( 'عفواً، لا تملك الصلاحية لتنفيذ هذا الإجراء.' );
}

4. الهروب المتأخر جداً (Escape as Late as Possible)

هذه القوانين تُعد من أشهر وأهم القواعد في مراجعات الأكواد الرسمية بووردبريس (WordPress Code Review Guidelines).

ماذا تعني؟ تعني ألا تقوم بتطهير المخرجات (Escaping) في بداية الكود أو داخل المتغيرات المؤقتة، بل في لحظة طباعتها بـ echo مباشرة أمام عينيك!

❌ ممارسة خاطئة (Early Escaping):

wrong-early-escaping.php
<?php
$user_title = esc_html( $data['title'] ); // تطهير مبكر في بداية الملف

// ... 50 سطر كود برمجية ومعالجات ...

echo $user_title; // ❌ طباعة بدون Escaping في لحظتها (قد ينسى المطور هل تم تطهيرها أم لا)

✅ الممارسة الصحيحة والآمنة (Late Escaping):

correct-late-escaping.php
<?php
$user_title = $data['title']; 

// ... 50 سطر كود برمجية ومعالجات ...

// ✅ التطهير والـ Escaping يتم في لحظة الـ echo مباشرة أمام العين!
echo esc_html( $user_title );

🛡️ أشهر دوال التطهير والهروب (Escaping Functions) للاستخدام اليومي:

دالة الـ Escaping السياق والمكان المستهدف مثال الاستخدام في الكود
esc_html() لطباعة النصوص العادية داخل عناصر HTML مثل <p> أو <span>. <span><?php echo esc_html( $title ); ?></span>
esc_attr() لطباعة القيم داخل خصائص HTML مثل value="..." أو alt="...". <input type="text" value="<?php echo esc_attr( $name ); ?>" />
esc_url() لطباعة الروابط والعناوين داخل href="..." أو src="...". <a href="<?php echo esc_url( $link ); ?>">رابط</a>
wp_kses_post() عند السماح بنصوص تحتوي على HTML آمن (مثل المحتوى) وتجريد السكريبتات الخبيثة. <div class="content"><?php echo wp_kses_post( $html ); ?></div>

2. أدوار وصلاحيات المستخدمين (User Roles & Capabilities)

كل مستخدم مسجل في ووردبريس ينتمي إلى **دور (User Role)** معين (مثل Administrator, Editor, Author, Subscriber). ينطوي كل دور على مجموعة من **الصلاحيات (Capabilities)** المحددة سلفاً (مثل manage_options للمسؤول أو edit_others_posts للمحرر).

الدور (Role) الصلاحية الشهيرة (Capability) الوصف والإمكانية السماحية
Administrator manage_options التحكم الكامل في الخيارات وتعديل إعدادات الموقع والإضافات.
Editor edit_others_posts تحرير وإدارة ونقل مقالات المستخدمين الآخرين لسلة المهملات.
Author publish_posts كتابة ونشر المقالات الخاصة بالمؤلف فقط.
Subscriber read قراءة المحتوى فقط دون أي صلاحيات تعديل أو إدارة.

3. تطبيق عملي: ثغرة رابط الحذف وبناء الحماية بـ current_user_can()

الكود الضعيف والمخترق (Unrestricted Vulnerable Code)

الكود التالي يُنشئ رابطاً لحذف المقال في الواجهة الأمامية، ولكن دون فحص صلاحيات المستخدم! يمكن لأي زائر غير مسجل الضغط على الرابط ونقل المقالات للـ Trash!

vulnerable-delete-link.php
<?php
// ❌ كود خطير: يسمح لأي زائر بحذف المقال دون فحص صلاحياته!
function wporg_delete_post() {
    if ( isset( $_GET['action'] ) && 'wporg_frontend_delete' === $_GET['action'] ) {
        $post_id = isset( $_GET['post'] ) ? (int) $_GET['post'] : null;
        if ( ! empty( $post_id ) ) {
            wp_trash_post( $post_id ); // كارثة أمنية!
            wp_safe_redirect( admin_url( 'edit.php' ) );
            exit;
        }
    }
}
add_action( 'init', 'wporg_delete_post' );

الكود الآمن المحمي (Restricted with current_user_can)

لحظر الزوار والمشتركين ومنح الصلاحية للمحرر والمسؤول فقط، نغلف الـ Filter والـ Action بالفحص القياسي current_user_can('edit_others_posts'):

secure-delete-link.php
<?php
// ✅ كود آمن: لا يُنفذ إلا إذا كان المستخدم يملك صلاحية edit_others_posts
function wporg_add_delete_post_ability() {
    if ( current_user_can( 'edit_others_posts' ) ) {
        add_filter( 'the_content', 'wporg_generate_delete_link' );
        add_action( 'init', 'wporg_delete_post' );
    }
}
add_action( 'plugins_loaded', 'wporg_add_delete_post_ability' );
