التلخيص المترابط للموضوعات

تم دمج الأفكار المتشابهة والمكملة لبعضها من النصوص المدخلة تحت أقسام موضوعية واضحة للمذاكرة.

1. ## ١. القاعدة الذهبية لتطوير ووردبريس واستقلالية النواة

تعليم ووردبريس

١.١ مفهوم القاعدة الذهبية (The Cardinal Rule)

تُعد القاعدة الأساسية والأولى في عالم تطوير ووردبريس هي:
> ⚠️ تنبيه امتحاني هام (The Cardinal Rule):
> لا تقم مطلقاً بتعديل ملفات النواة المباشرة لـ ووردبريس (Don't touch WordPress core).

١.٢ المخاطر والأسباب العلمية للحظر


1. فقدان التعديلات مع التحديثات: تقوم منصة ووردبريس بتحديث ملفات النواة تلقائياً أو يدوياً بصورة دورية لمعالجة الثغرات الأمنية أو إضافة ميزات جديدة، مما يؤدي إلى مسح كلي لأي تعديلات برمجية أُجريت داخل النواة.
2. الانهيار البرمجي والتداخل (Conflicts): التعديل المباشر يزيد من احتمالية حدوث تعارضات خطيرة مع القوالب والإضافات الأخرى.
3. صعوبة الصيانة: يصعب تتبع التغييرات وصيانتها عند مزج شفرات التطبيق المخصص مع شفرات النواة الأصلية.

١.٣ الحل المعماري: الإضافات (Plugins)


* التعريف: الإضافة (Plugin) هي وحدة برمجية مستقلة تُكتب بلغة PHP لتوسيع أو تعديل وظائف ووردبريس دون مساس بالنواة.
* الغاية: توفير التوافقية المستدامة وتأمين النظام ضد ضياع البرمجيات عند التحديث.

| وجه المقارنة | تعديل النواة (Modifying Core) | استخدام الإضافات (Using Plugins) |
| :--- | :--- | :--- |
| تأثير التحديثات | تُحذف كافة التعديلات فوراً | تظل التعديلات قائمة ومستقلة |
| الأمان والصيانة | منخفض جداً وعرضة للاختراق | عالٍ ويخضع لأفضل الممارسات |
| التوافق والتكامل | يتسبب في تعارض الكود | يعتمد على خطاطيف رسمية (Hooks) |

2. ## ٢. التشريح الهيكلي للإضافة والمكونات الأساسية

تعليم ووردبريس

٢.١ أبسط أشكال الإضافات (The Simplest Plugin)


يمكن للإضافة في ووردبريس أن تكون بسيطة للغاية أو على درجة عالية من التعقيد بحسب الحاجة البرمجية:
* الإضافة البسيطة: تتكون من ملف PHP واحد فقط يوضع داخل مجلد الإضافات (`wp-content/plugins/`).
* مثال توضيحي مشهور: إضافة Hello Dolly المعيارية المرفقة مع ووردبريس.

٢.٢ المتطلبات البرمجية الثلاثة للإضافة البسيطة


كي يتعرف ووردبريس على الملف كإضافة صالحة للعمل، يجب أن يحتوي الملف على ثلاثة عناصر رئيسية:
1. رأس الإضافة (Plugin Header): تعليق برمجي ذو صيغة خاصة في بداية الملف يحتوي على معلومات الإضافة.
2. دوال PHP المخصصة (Custom PHP Functions): الأكواد والوظائف المراد تنفيذها.
3. الخطاطيف (Hooks): ربط الدوال المخصصة بنقاط الأحداث داخل ووردبريس.

٢.٣ نموذج برمجي لرأس الإضافة (Plugin Header Code Block)

```php
/*
Plugin Name: My Custom Academic Plugin
Plugin URI: https://example.com/my-plugin
Description: إضافة تعليمية توضح كيفية بناء إضافة ووردبريس معيارية.
Version: 1.0.0
Author: Academic Developer
Author URI: https://example.com
License: GPL2
*/

// منع الوصول المباشر للملف لأسباب أمنية
if ( ! defined( 'ABSPATH' ) ) {
exit; // Exit if accessed directly
}
```

> 💡 ملاحظة للمذاكرة: رأس الإضافة (Plugin Header) هو العنصر الوحيد الإجباري لتسجيل الإضافة في لوحة تحكم ووردبريس، وبدونه لن يتعرف النظام على الملف كإضافة.

3. ## ٣. آلية عمل الخطاطيف (WordPress Hooks Architecture)

تعليم ووردبريس

٣.١ مفهوم الخطاطيف (Hooks Concept)


الخطاطيف هي الآلية الرئيسية التي تسمح للإضافات بالتفاعل مع ووردبريس دون تعديل ملفات النواة.

٣.٢ أنواع الخطاطيف الرئيسية


1. الأفعال/الإجراءات (Actions):
* تُستخدم لإضافة أو تنفيذ وظائف معينة عند نقطة زمنية أو حدث محدد في دورة حياة النظام.
* الدالة المعيارية: `add_action( $tag, $function_to_add )`
2. الفلاتر/المرشحات (Filters):
* تُستخدم لتعديل أو معالجة البيانات والمعلومات قبل عرضها أو حفظها في قاعدة البيانات.
* الدالة المعيارية: `add_filter( $tag, $function_to_add )`

٣.٣ مثال برمجي على تطبيق الخطاطيف

```php
// دالة مخصصة لإضافة نص في أسفل الموقع
function academic_custom_footer_text() {
echo '

تم تطوير هذا الموقع باستخدام إضافات معيارية.

';
}
// ربط الدالة بخطاف الإجراء الخاص بأسفل الصفحة
add_action( 'wp_footer', 'academic_custom_footer_text' );
```

4. ## ٤. الممارسات الأمنية المعيارية والمعايير البرمجية

تعليم ووردبريس

٤.١ تأمين الإضافات (Plugin Security Best Practices)


يشير دليل مطوري الإضافات إلى أهمية اتباع أفضل الممارسات الأمنية لضمان سلامة الموقع:
1. التحقق من صلاحيات المستخدمين (Capability Checks): التأكد من أن المستخدم الحالي يمتلك الصلاحيات الكافية قبل تنفيذ العمليات الحساسة.
2. التحقق من صحة البيانات وتطهيرها (Data Sanitization & Validation): تنظيف جميع البيانات المدخلة من المستخدمين قبل معالجتها.
3. الهروب الآمن للمخرجات (Output Escaping): تأمين البيانات المعروضة في المتصفح للحماية من ثغرات النص البرمجي عبر المواقع (XSS).
4. التحقق من الرموز الأمنية المؤقتة (Nonces): استخدام مفاتيح أمان لحماية الاستشارات من هجمات تزوير الطلبات عبر الموقع (CSRF).

> ⚠️ تنبيه امتحاني هام: يجب دائماً تضمين سطر المنع المباشر `if ( ! defined( 'ABSPATH' ) ) exit;` في بداية كل ملف PHP لمنع الاستدعاء المباشر واستغلال الملفات خارج بيئة ووردبريس.

  • • استخدام لغة JavaScript بدلاً من PHP
  • • حذف الملفات الأصلية واستبدالها
✅ الإجابة النموذجية: عدم تعديل ملفات نواة ووردبريس اطلاقاً (Don't touch WordPress core)

الشرح والمراجعة: القاعدة الأساسية المنصوص عليها هي عدم تعديل ملفات النواة مباشرة لأن التحديثات الدورية ستؤدي إلى كتابة فوقية تعيد إرجاع الملفات لحالتها الأصلية وتحذف أي تعديلات مخصصة.

سؤال 2 (اختيار من متعدد) سهل

  • • تُحفظ تلقائياً في قاعدة البيانات
  • • تندمج تلقائياً مع التحديث الجديد
  • • تُحذف وتُستبدل بالملفات الجديدة للتحديث
  • • تتحول إلى إضافة مستقلة
✅ الإجابة النموذجية: تُحذف وتُستبدل بالملفات الجديدة للتحديث

الشرح والمراجعة: يقوم ووردبريس بإعادة كتابة جميع ملفات النواة عند التحديث، مما يؤدي لمسح جميع التغيرات البرمجية التي تمت داخل تلك الملفات.

المصدر: تعليم ووردبريس

الشرح والمراجعة: إذا حاول شخص استدعاء الملف مباشرة عبر الرابط، يجد أن الثابت ABSPATH غير معرف فيتوقف التنفيذ فوراً.

✅ الإجابة النموذجية: تُستخدم الأفعال (Actions) لإضافة وظائف جديدة أو تنفيذ مهام عند حدث معين، بينما تُستخدم الفلاتر (Filters) لتعديل ومعالجة البيانات قبل عرضها أو حفظها.

الشرح والمراجعة: الـ Action ينفذ أمراً أما الـ Filter فيستلم مخرجات ويعدلها ثم يعيدها.
